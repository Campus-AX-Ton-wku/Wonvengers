# 온통청년 API 연동

앱은 정책 목록을 보여줄 때, 그 정책이 **정부 청년정책 DB(온통청년)에 어떻게 등록되어 있는지**를 함께 표시한다. `/find`(1층)와 `/result`(2층) 두 화면에 나온다.

## 화면에 뭐가 보이나

정책 카드마다 배지가 하나 붙는다.

| 배지 | 뜻 |
|---|---|
| ✓ 온통청년 등록 확인 | 정부 DB에 등록돼 있고, 앱 데이터와 어긋나는 항목이 없다 |
| 온통청년 공고와 차이 | 등록돼 있지만 신청기간·나이·정책명 중 하나 이상이 다르다 |
| 온통청년 미등록 | 정부 DB에서 이 정책을 찾지 못했다 |

`공고와 차이`인 경우 **무엇이 어떻게 다른지**를 그대로 펼쳐 보여준다. 예를 들면 이렇게 나온다.

```
신청 종료일: 앱 2026-12-31 / 온통청년 2026-09-30
```

> [!IMPORTANT]
> 차이를 숨기지 않는 것이 이 기능의 핵심이다. 정부 DB와 다른데 조용히 앱 값만
> 보여주면, "대조했다"는 표시 자체가 사용자를 잘못 안심시킨다.

## 갱신하는 방법

### 1. 인증키 발급 (한 번만)

1. [온통청년](https://www.youthcenter.go.kr) 회원가입 후 로그인
2. [마이페이지 → OPEN API](https://www.youthcenter.go.kr/myPage/openapi)에서 인증키 신청
3. **담당자 승인 심사**를 거친다. 즉시 발급이 아니다.

### 2. 키를 로컬에 저장

`apps/web/.env.local` 파일을 만들고 한 줄 넣는다.

```
YOUTH_API_KEY=발급받은-키
```

이 파일은 `.gitignore`에 걸려 있어 저장소에 올라가지 않는다. 팀원은 각자 만든다.

### 3. 갱신 실행

```bash
cd apps/web
npm run fetch:youth
```

두 개가 갱신된다.

- `apps/web/data/youth-policy-index.json` — 화면이 읽는 대조 색인
- `docs/기획/온통청년-주거후보.md` — 1층 정책을 늘릴 때 쓰는 후보 목록

터미널에 정책별 대조 결과가 바로 찍힌다. `불일치`가 뜬 정책은 공고 원문을 확인해
`policies.json`을 고쳐야 한다는 뜻이다.

## 왜 실시간 호출이 아닌가

앱은 실행 중에 API를 부르지 않는다. 빌드 전에 미리 받아 파일로 굽는다. 이유가 네 개다.

1. **서버가 없다.** `next.config.ts`가 `output: "export"`인 정적 배포다. 호출을 대신해 줄 서버가 없다.
2. **브라우저에서 직접 못 부른다.** 이 API는 `Access-Control-Allow-Origin` 헤더를 주지 않고 프리플라이트(OPTIONS)가 403이다. 브라우저가 막는다.
3. **키가 노출된다.** 클라이언트 코드에 키를 넣으면 누구나 개발자도구로 볼 수 있다.
4. **같은 입력은 같은 결과를 내야 한다** (PRD F3-2). 화면이 매번 외부 응답에 따라 달라지면 그 보장이 깨지고, 발표 중 API가 죽으면 화면도 죽는다.

색인 파일은 저장소에 커밋한다. 그래서 **배포할 때는 키가 필요 없다.** Vercel은 커밋된 파일만 읽는다.

## 지켜야 할 규칙

> [!CAUTION]
> **API에서 받은 값을 판정이나 금액 계산에 쓰지 않는다.**

`youth-policy-index.json`은 화면 표시 전용이다. 자격 판정과 금액은 `policies.json`만 근거로 한다. 이유는 두 가지다.

- API의 기록도 낡을 수 있다. 실제로 `전북청년 지역정착 지원사업`은 API에 **2025년 회차**만 등록돼 있다. 이걸 그대로 판정에 넣으면 마감된 사업으로 잘못 처리한다.
- API가 주는 지원 조건은 대부분 산문(`plcySprtCn`)이다. 소득 상한 %, 보증금·월세 상한 같은 판정에 필요한 숫자를 기계가 정확히 뽑아낼 수 없다. 추정해서 채우면 PRD의 "추측하지 않는다" 원칙이 깨진다.

정리하면 이렇다.

```
policies.json          → 자격 판정 · 금액 계산   (사람이 공고 보고 검수)
youth-policy-index.json → 출처 대조 표시만       (스크립트가 자동 생성)
```

## 정책을 새로 추가할 때

1. `docs/기획/온통청년-주거후보.md`에서 후보를 고른다
2. **공고 원문을 직접 열어** 조건을 확인한다 (후보 목록에는 다른 시·도 사업과 개인이 신청할 수 없는 사업 계획도 섞여 있다)
3. `policies.json`에 정책을 추가하고, 후보 목록의 `plcyNo`를 `youthPolicyNo` 필드에 넣는다
4. `npm run fetch:youth`를 다시 돌린다
5. `npm test`로 색인 연결이 맞는지 확인한다

온통청년에 없는 정책이면 `youthPolicyNo`를 `null`로 둔다. 화면에 `미등록`으로 표시된다.

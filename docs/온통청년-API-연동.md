# 온통청년 API 연동 (내부 발굴 도구)

정책 출처는 **지역 공고 하나**로 간다. 앱은 정책 카드에서 `policies.json` 의
`sourceUrl`(공고 원문)과 `verifiedAt`(팀이 대조한 날짜)만 보여준다.

온통청년 API 는 **화면에 나가지 않는다.** 팀이 다음에 어떤 정책을 추가할지 고르는
발굴 도구로만 쓴다.

## 왜 화면에서 뺐나

한때 정책 카드에 `✓ 온통청년 등록 확인` / `온통청년 공고와 차이` / `온통청년 미등록`
배지를 붙였다. 커버리지가 그 표현을 뒷받침하지 못해서 걷어냈다 (2026-08-24).

| 확인한 사실 | 그래서 |
|---|---|
| 익산 시군구코드(`52140`) + 대분류 `주거` 로 조회한 27건에 **경상북도 의성군 사업 6건**이 섞여 들어왔다 | 지역 필터를 믿을 수 없다 |
| 같은 27건에 **익산시 전입 청년 이사비·중개보수 지원사업이 없다** | 익산 사업이 빠져도 알 수 없다 |
| 조회를 대분류 `주거` 하나로만 했다 | 다른 분류에 등록된 정책을 두고 "없다"고 말할 근거가 없다 |
| 후보 목록에 `20240226 ~ 20250225` 처럼 이미 끝난 신청기간이 그대로 등록돼 있다 | 등록 정보 자체가 낡는다 |

즉 `미등록` 배지는 "온통청년에 없다"가 아니라 **"아무도 정책번호를 매핑하지 않았다"**
였다. 찾아본 적이 없는데 찾지 못했다고 말하는 화면이었다.

> [!IMPORTANT]
> 확인한 사실만 말한다. 사용자에게 보여주는 출처는 팀이 직접 공고와 대조한
> `sourceUrl` 하나이고, 대조하지 않은 정책(`verifiedAt: null`)은 카드에서 그렇게 밝힌다.

주거급여 분리지급처럼 소관이 다른 정책은 온통청년이 애초에 사본이다
(원본은 복지로·마이홈). 이것도 단일 출처로 쓸 수 없는 이유다.

## 갱신하는 방법

### 1. 인증키 발급 (한 번만)

1. [온통청년](https://www.youthcenter.go.kr) 회원가입 후 로그인
2. [마이페이지 → OPEN API](https://www.youthcenter.go.kr/myPage/openapi)에서 인증키 신청
3. **담당자 승인 심사**를 거친다. 즉시 발급이 아니다.

### 2. 키를 로컬에 저장

`apps/web/.env.local` 파일을 만들고 한 줄 넣는다.

```
YOUTH_API_KEY=발급받은-키
```

이 파일은 `.gitignore`에 걸려 있어 저장소에 올라가지 않는다. 팀원은 각자 만든다.

### 3. 실행

```bash
cd apps/web
npm run fetch:youth
```

산출물은 하나다.

- `docs/기획/온통청년-주거후보.md` — 1층 정책을 8~12개로 늘릴 때 볼 후보 목록

터미널에는 이미 정책번호를 매핑해 둔 정책의 등록 정보가 앱 데이터와 어긋나는 지점이
찍힌다. **어느 쪽이 맞는지는 스크립트가 알 수 없다** — 공고를 다시 볼지 판단하는
힌트일 뿐이다. 이 값은 파일로 남기지 않고 화면에도 나가지 않는다.

배포할 때 키는 필요 없다. Vercel 이 읽는 건 커밋된 `policies.json` 뿐이다.

## 지켜야 할 규칙

> [!CAUTION]
> **API에서 받은 값을 판정·금액 계산에도, 사용자 화면에도 쓰지 않는다.**

- API의 기록도 낡는다. `전북청년 지역정착 지원사업`은 API에 **2025년 회차**만 등록돼
  있다. 그대로 판정에 넣으면 마감된 사업으로 잘못 처리한다.
- API가 주는 지원 조건은 대부분 산문(`plcySprtCn`)이다. 소득 상한 %, 보증금·월세
  상한 같은 판정에 필요한 숫자를 기계가 정확히 뽑아낼 수 없다. 추정해서 채우면
  PRD의 "추측하지 않는다" 원칙이 깨진다.

```
policies.json        → 자격 판정 · 금액 계산 · 화면 출처 표시  (사람이 공고 보고 검수)
온통청년 API          → 다음에 추가할 정책 후보 찾기            (스크립트, 화면에 안 나감)
```

## 정책을 새로 추가할 때

1. `docs/기획/온통청년-주거후보.md`에서 후보를 고른다
2. **공고 원문을 직접 열어** 조건을 확인한다 (후보 목록에는 다른 시·도 사업과 개인이
   신청할 수 없는 사업 계획도 섞여 있다)
3. `policies.json`에 정책을 추가한다 — `sourceUrl` 에 공고 원문 주소, `verifiedAt` 에
   확인한 날짜, `notes` 에 원문에서 읽은 근거를 적는다
4. 후보 목록의 `plcyNo`를 `youthPolicyNo` 필드에 넣는다 (없으면 `null`). 이 값은
   같은 정책이 후보 목록에 다시 올라오지 않게 하는 용도이고, 화면에는 쓰지 않는다
5. `npm test` 로 형식이 맞는지 확인한다

지역 공고 트랙은 손으로 유지한다. 공고가 새로 나오면 `sourceUrl`·`verifiedAt`·`notes`
와 정책 수치를 사람이 직접 갱신한다.

# 화면 구조 개편 설계 — 단계형 질문 흐름과 밀도 정리

작성일 2026-08-30 · 대상 `/find`, `/find/policies`, `/calculate`, `/eligibility`, `/result`

## 왜

만 40세 이상을 고를 수 있게 열어 둔 나이 목록에 "해당되는 지원금 없음"이라는 라벨이
붙어 있었다. 그 어색함을 고치는 과정에서 같은 뿌리를 가진 문제들이 드러났다 —
입력란에 판정을 얹은 것, 못 받는 것을 받을 수 있는 것과 같은 숫자로 센 것, 그리고
정보를 전부 테두리 친 상자에 담아 무엇이 중요한지 화면이 말해주지 않는 것.

토스 앱 스크린샷 80장(온보딩·계좌·송금·신용·카드)을 레퍼런스로 받아 검토했다.
아래는 거기서 읽어낸 규칙과, Perky 에 적용할 방식이다.

## 레퍼런스에서 읽어낸 것

실제로 확인한 화면 기준이다.

**한 화면 한 질문, 답한 것은 아래로 쌓인다.**
"이름을 입력해주세요" 를 답하면 그 질문이 아래로 밀리고 "주민등록번호를
입력해주세요" 가 새 제목이 된다. 스텝 번호도 진행바도 없다 — 쌓인 답 자체가 진행
표시다. 질문이 곧 페이지 제목이고 이모지는 없다.

**테두리를 거의 쓰지 않는다.**
계좌 목록·카드 목록 전부 무테다. 흰 배경 위에 여백과 hairline 구분선만으로 그룹을
나눈다. 강조가 필요한 블록은 테두리 대신 연회색 면으로 채운다.

**라벨은 작게 위에, 값은 크게 아래에.**
`신한금융투자 CMA`(작은 회색) / `2,200 원`(큰 볼드). 값은 항상 좌측 정렬로 크게 온다.

**요약 숫자가 화면 맨 위에 온다.**
`총 계좌 잔액 / 112,841 원`. 작은 라벨 + 아주 큰 숫자가 첫 화면을 지배한다.

**색은 예외에만 쓴다.**
`45점 상승` 은 파랑 틴트, `4점 하락` 은 회색 틴트. 무채색이 기본이고 색은
긍정·행동 가능한 상태를 표시할 때만 나온다.

## 가져오지 않는 것

**토스 팔레트는 이식하지 않는다.** Perky 는 sand 배경(`#f5efeb`) + slate
blue(`#567c8d`) + terracotta 금액(`#a85434`) 의 따뜻한 세계다
(`apps/web/app/globals.css`). 토스의 흰 배경 + 전기 블루로 바꾸면 앱의 정체성이
사라진다. 가져오는 것은 구조·밀도·타이포 위계 세 가지다.

## 무엇을 바꾸나

### 1. 하나의 연속 흐름

`/find`(4단계) → `/calculate`(2단계) → `/eligibility`(N단계) 를 한 흐름의 단계로
통일한다. 뒤 두 화면은 이미 `AppBar` + `StepHeading` + `BottomCta` 를 공유하므로
(`apps/web/app/Stepper.tsx`) 1층만 합류시키면 된다.

질문이 곧 페이지 제목이다. 카드도, `질문 1` 번호도, 이모지도 없앤다. 답한 질문은
아래로 밀려 `라벨(작은 회색) / 값(중간 볼드)` 2줄 행으로 쌓인다.

```
어디에 살거나
살 예정인가요?

[익산시] [전북 그 외] [그 외 지역] [모름]

──────────────────────────────
생년월일
1998년 3월 14일 · 만 28세
```

### 2. 진행바를 없앤다

쌓인 답이 진행 표시다. 상단에는 뒤로가기만 남는다. 1층 4 + 계약 2 + 2층 N 을
합치면 10단계가 넘는데, 그 숫자를 `3/10` 으로 먼저 보여주면 시작하기 전에 질린다.

`AppBar` 의 `current`/`total` 인터페이스가 사라지므로 `Stepper.tsx` 가 바뀐다.

### 3. 실시간 건수는 CTA 에 살린다

`다음` 대신 `지원금 3건 · 다음`. 답할수록 5 → 3 → 2 로 좁혀지는 게 보여야 계속
답할 이유가 된다. 지금 1층의 가장 큰 장점이고 단계형으로 옮기며 잃기 쉬운 부분이다.

### 4. 답변 고치기는 마지막 단계로 보낸다

마지막 스텝에는 4개 답이 전부 쌓여 있다. 목록의 `답변 고치기` 를 그 스텝으로
보내고, 쌓인 각 행을 탭하면 그 질문으로 돌아간다.

### 5. 테두리를 걷어낸다

| 지금 | 바꿀 것 |
| --- | --- |
| 질문 4개가 `rounded-2xl border` 카드 | 테두리 없음, 구분선과 여백만 |
| 정책 카드마다 `border border-ink-200` | 무테 행, 그룹만 hairline 으로 나눔 |
| 강조 블록도 테두리 | 테두리 대신 `sand-50`/`brand-50` 면으로 채움 |

### 5-2. 결과 요약을 별도 화면으로 (`/find/result`)

질문 네 개에 답한 보상이 목록 맨 위 세 줄로 스쳐 지나갔다. 바로 아래에서 카드가
시선을 가져가 큰 숫자를 볼 틈이 없었다. 요약을 자기 화면으로 떼어 낸다.

```
/find (4단계 질문) → /find/result (결과 요약) → /find/policies (목록) → /calculate
```

요약 화면은 금액과 건수만 크게 말한다. 다만 숫자만 덩그러니 두지는 않는다 —
답변 칩과 마감 건수는 "왜 이 숫자인지"를 설명하므로 함께 둔다.

후보가 있는데 전부 마감이면 여기서 그 사실을 말한다. '해당되는 지원금이 없어요'
로 뭉뚱그리면 대상이 아니라는 뜻으로 읽히지만, 실제로는 다음 회차를 기다리면 된다.

**목록 화면의 금액 헤드라인은 뺀다.** 앞 화면에서 방금 본 숫자를 다시 보여주면
같은 말을 두 번 하는 셈이다. 목록은 제목만으로 시작한다.

참고로 이 분리는 레퍼런스에서 직접 본 화면은 아니다. 토스 홈-계좌·홈-카드는 요약과
목록이 한 화면이고, 가장 가까운 것은 홈-카드의 `결제할 카드값 [보기]` 처럼 칩을
눌러 상세로 들어가는 패턴이다. 질문 흐름을 마친 뒤 결과를 발표하는 화면은 그와
별개로 타당하다고 판단해 채택했다.

### 6. 라벨 작게 위, 값 크게 아래

```
지금:  청년월세 지원 (2026년 상시사업 전환)      가능성 있음
       국토교통부 · 월세 지원              최대 480만원   ← 우측 작게

바꿈:  국토교통부 · 월세 지원              ← 작은 회색
       최대 480만원                       ← 큰 볼드, 좌측
       청년월세 지원 (2026년 상시사업 전환)
```

목록 헤드라인도 같은 규칙으로 세운다.

```
지금 신청할 수 있는
최대 480만원
지원금 2건
```

**합산하지 않는다.** 중복 수급 제한(`exclusiveGroup`) 때문에 상한을 더하면 거짓이
된다. 정확한 조합은 계약 조건이 있어야 `bestCombination` 이 계산할 수 있으므로
1층에서는 불가능하다. 가장 큰 한 건만 말한다.

### 7. 색은 행동 가능한 상태에만

- 마감 카드의 `가능성 있음` 태그 → 회색 틴트. 문구는 그대로 두어 PRD F3-6
  ("1층 태그는 나이·지역·상태·소득만 본다") 의 의미를 지킨다
- 마감 카드의 금액도 accent terracotta → 무채색
- 색은 지금 신청할 수 있는 것에만 남는다

## 손대지 않는 것

판정 로직(`filter.ts`·`policy-rules.ts`·`combinations.ts`), 정책 데이터, 고지 문구,
공고 출처·검수 날짜 표기, 로컬 전용 저장(PRD F0-13), 생년월일 1층↔2층 동기화.

**안티골:** 토스 팔레트 이식, 정보를 숨겨 화면을 예쁘게 만들기, 금액 합산.

## 다뤄야 할 상태

정책 5건 · 후보 0~5건 · 마감 0~2건 · 2층 질문 4~15개(지역별).

첫 방문(전부 모름), 후보 0건, **후보는 있는데 전부 마감**, 나이 범위 밖, 저장값 없는
상태, 불러오는 중.

## 위험

**1층 → 목록 왕복이 무거워진다.** 지금은 한 화면에서 답을 고치고 즉시 건수를 본다.
단계형에서는 4스텝을 지나야 한다. "마지막 스텝으로 보내기" 로 완화하지만 완전히
상쇄되지는 않는다.

**이모지 제거는 취향이 갈린다.** 토스에는 없지만 Perky 의 따뜻한 톤에는 기여한다.
질문 제목에서만 빼고 다른 곳은 남긴다.

**변경 범위가 크다.** 5개 라우트 + `Stepper.tsx` + 화면 테스트 다수. 자동 테스트
297개 중 화면 테스트가 스텝 구조에 묶여 있어 상당수를 다시 써야 한다.

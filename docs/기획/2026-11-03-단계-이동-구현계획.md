# 단계 이동 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 휴대폰 뒤로가기와 왼쪽 위 화살표가 어느 질문 화면에서든 바로 전 단계로 가고, 고른 답이 상단바 아래 한 줄에 늘 보인다.

**Architecture:** 질문 단계를 컴포넌트 상태에서 주소(`?q=` / `?s=` / `?g=`)로 옮긴다. `lib/navigation.ts` 의 `useStepParam` 이 주소 ↔ 단계를 맡고, `useBack` 이 "앞 화면이 앱 안이면 `history.back()`, 이 탭의 첫 화면이면 정해 둔 상위 화면"을 판단한다. 첫 화면 기록은 `lib/entry.ts`(React 없음)의 `<head>` 인라인 스크립트가 sessionStorage `perky.entry` 에 남긴다. 고른 답은 공통 컴포넌트 `AnswerSummaryBar` 가 상단바 아래 sticky 한 줄로 그린다.

**Tech Stack:** Next.js 15 App Router (static export), TypeScript, Tailwind 4, Vitest 2 + Testing Library (jsdom), Playwright 1.62 (검증 스크립트)

**Spec:** `docs/기획/2026-11-03-단계-이동-설계.md`

## Global Constraints

- 뒤로 버튼 문구는 `"이전 단계로"` 하나다. 화면마다 다른 문구를 두지 않는다
- 단계 주소: `/find` → `?q=birth` `region` `status` `income` `housing`, 시군구 목록은 `?q=region&p=<시도명>` · `/calculate` → `?s=1` `2` · `/eligibility` → `?g=1` `2` `3`
- "다음"은 `router.push`(기록 +1). 주소에 단계가 없거나 앞 단계를 건너뛴 주소면 `router.replace`(기록 그대로)
- 첫 진입 기록 키: sessionStorage `perky.entry`. sessionStorage 가 막히면 항상 `backHref` 로 간다
- `useSearchParams` 를 쓰는 페이지는 본문을 `<Suspense>` 안에 둔다(정적 export 요구)
- 화면별 `backHref`: `/find` → `/`, `/find/result` → `/find`, `/find/policies` → `/find/result`, 정책 상세 → `/find/policies`, 신청 준비 → 정책 상세, `/calculate` → `/find/policies`, `/eligibility` → `/calculate`, `/result` → `/eligibility`, 요건 검토 → `/result`
- `app/result/BenefitResultCard.tsx`, `lib/benefit-result.ts`, `app/result/ResultState.tsx` 는 건드리지 않는다 (`TopBar` 의 `backHref` 의미가 바뀌어 `ResultState` 도 함께 고쳐진다)
- 공통 컴포넌트는 `app/components/index.ts` 로만 export·import 한다
- 터치 타깃 최소 44px (`min-h-11` / `h-11`)
- 자동 스크롤은 `prefers-reduced-motion: reduce` 이면 `behavior: "auto"`
- 선택해도 자동으로 다음 질문으로 넘어가지 않는다 — 지금처럼 "다음"
- `lib/steps.ts` 의 묶음·필터(판정 로직)는 바꾸지 않는다
- F0-5 추정 금지 — 이 계획은 데이터를 건드리지 않는다. 지역 약칭도 `REGION_HIERARCHY` 에 이미 있는 `chipLabel` 만 쓴다
- push·PR 은 사용자가 요청할 때만. 로컬 커밋만

## 작업 환경

`apps/web/node_modules` 는 Windows 에서 설치돼 WSL 에서 테스트가 돌지 않는다. 이 계획은 scratchpad
worktree(`…/scratchpad/iksan`, 브랜치 `feature/step-navigation`, `npm ci` 완료)에서 실행한다.
모든 명령은 `apps/web` 에서:

```
node node_modules/vitest/vitest.mjs run <파일>     # 단일 테스트
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vitest/vitest.mjs run           # 전체 (시작 시점 498개 통과)
npm run build
```

브랜치는 `feature/iksan-trusted-data` 위에 있다(`/find`·`/find/policies` 를 양쪽이 고친다). 익산 PR 이
머지되면 `git rebase origin/develop`. 머지 순서는 익산 PR → 이 PR.

⚠️ 이 worktree 에서 dev 서버가 `:3000` 으로 떠 있다. **끄지 말 것.** `npm run build` 는 실행 중인 dev
서버의 `.next` 를 깨뜨린다(CLAUDE.md, `Cannot find module './XXX.js'` 500). 그래서 Task 1~6 은
vitest·tsc 로만 확인하고, 빌드는 Task 7 에서 한 번 한 뒤 dev 서버를 다시 띄운다.

## 설계를 코드로 옮기며 정한 해석

설계 문서가 열어 둔 곳을 이렇게 메웠다. 각 Task 가 이 해석을 따른다.

1. **작업 순서** — 설계의 1번(이동 기반)을 둘로 나눴다. Task 1 은 동작이 바뀌지 않는 기반(lib·테스트 대역),
   Task 2 는 `TopBar` 를 뒤로가기로 바꾸면서 세 질문 화면의 단계를 주소로 옮긴다. `onBack` 을 없앤 순간
   화면 안 단계가 주소에 없으면 화살표가 이전 질문으로 못 가서 테스트가 깨진다 — 그래서 설계 2·3·4번의
   "단계 주소" 부분을 Task 2 로 당겼다. Task 3·4·5 는 요약 줄·진행 표시·접기만 남는다.
2. **첫 화면에서의 화살표** — 설계는 `router.push(backHref)` 라고 했지만 `replace` 하고 첫 화면 기록을
   `backHref` 로 옮긴다. push 로 가면 `backHref` 화면의 화살표가 `history.back()` 으로 방금 떠난 화면에
   돌아가 두 화면 사이를 오간다(링크로 `/result` 에 바로 들어와 화살표 → `/eligibility` → 화살표 → 다시
   `/result`). replace 면 화살표가 계속 위로 올라가고, 앱 밖으로 나가는 건 맨 처음 화면에서만이다.
3. **replace 와 첫 화면 기록** — 첫 화면에서 `replace` 하면(`/find` → `/find?q=birth`, 온보딩 → `/find`,
   `/eligibility` → `/calculate`) 바뀐 주소가 여전히 첫 화면이므로 기록도 옮긴다(`replaceKeepingEntry`).
4. **`backLabel` prop** — 문구가 하나로 고정되지만 prop 은 받기만 하고 무시한다. `ResultState.tsx` 가 아직
   넘기고, 그 파일은 고치지 않는다.
5. **`AnswerSummaryBar` 를 그리는 조건** — "항목이 없으면 그리지 않는다"를 "항목도 `lead` 도 없으면"으로
   읽는다. `/eligibility` 첫 묶음은 앞 묶음이 없어도 진행 표시("1/3 기본 자격")는 보여야 한다.
6. **`/calculate`·`/eligibility` 의 첫 미답 단계** — 단계별 답 기록이 없으므로 지금처럼 첫 단계(`1`)로
   보낸다. 대신 앞 단계가 안 채워졌으면 그 뒤 단계 주소로 못 들어간다(`/calculate?s=2` 는 1단계 검증 통과,
   `/eligibility?g=k` 는 앞 묶음의 생년월일).
7. **`/eligibility` 의 "미답"** — 숫자·예/아니오 질문은 기본값이 이미 "모름"(선택된 것으로 보인다)이라
   넘어가기를 막는 미답은 생년월일 하나다(지금 규칙 그대로). "다음"이 막히면 그 질문으로 스크롤하고 제목에
   포커스한다. **접기**는 이번 방문에서 "고르면 끝나는" 질문(예/아니오/모름, 날짜 '확인')에 답했을 때만 한다.
   숫자 칸은 언제 다 쳤는지 알 수 없고, 칸을 떠날 때 접으면 다음 칸을 누르려던 손가락 밑에서 화면이 움직인다.
   목록(select)은 Windows 크롬에서 화살표 키 하나에도 change 가 나서 접지 않는다.
8. **질문 짧은 라벨** — 질문 정의는 `lib/steps.ts` 가 아니라 `lib/questions.ts` 의 `QUESTION_REGISTRY` 에
   있다. 거기 `shortLabel` 을 더한다.
9. **시도 약칭** — `REGION_HIERARCHY` 의 시도마다 이미 `chipLabel`(서울·부산·대구·인천·광주·대전·울산·세종·
   경기·강원·충북·충남·전북·전남·경북·경남·제주)이 있다. 새 표를 만들지 않고 그것을 쓴다. 겹치는 시군구는
   계산해 보면 중구·동구·서구·남구·북구·강서구·고성군 7개다.
10. **`/find` 요약 값** — 생년월일은 요약 줄에서 `만 23세`(나이를 아직 못 구하면 날짜)로 줄인다. 사는 곳
    항목은 시·군·구 목록(`?q=region&p=<시도>`)으로 바로 연다. 시·도 목록에서는 이미 답한 시도 카드를 선택된
    것으로 보여주고, 지역이 이미 답돼 있으면 "다음"을 누를 수 있다.
11. **온보딩 문구** — "네 가지"를 "다섯 가지"로 바꾸면서 나열에도 "주거 형태"를 더한다. 넷만 나열하고
    "다섯 가지"라고 하면 틀린 문장이 된다.

- [ ] **Step 1: 테스트 대역 작성** — `app/__tests__/navigation-mock.ts`

  테스트 파일이 아니라 다음 Step 의 테스트가 쓰는 도구라 먼저 만든다(`*.test.*` 가 아니어서 vitest 가 테스트로 집지 않는다).

```ts
/**
 * next/navigation 테스트 대역. vitest.setup.ts 가 모든 테스트 파일에 건다.
 *
 * 라우터를 jsdom 의 진짜 history 에 붙인다. push·replace 는 주소를 바꾸고 화면을 다시
 * 그리게 하며, history.back() 은 jsdom 이 popstate 를 내서 그 주소로 다시 그려진다.
 * 단계가 주소에 있는 화면(/find·/calculate·/eligibility)은 이게 없으면 "다음" 을 눌러도
 * 넘어가지 않는다.
 *
 * 파일 안에서 vi.mock("next/navigation", …) 을 따로 걸면 그쪽이 이긴다.
 */
import { useMemo, useSyncExternalStore } from "react";
import { vi } from "vitest";
import { ENTRY_KEY } from "@/lib/entry";

const listeners = new Set<() => void>();

function notify(): void {
  for (const listener of listeners) listener();
}

function subscribe(listener: () => void): () => void {
  listeners.add(listener);
  return () => {
    listeners.delete(listener);
  };
}

if (typeof window !== "undefined") window.addEventListener("popstate", notify);

export const routerMock = {
  push: vi.fn((href: string) => {
    window.history.pushState(null, "", href);
    notify();
  }),
  replace: vi.fn((href: string) => {
    window.history.replaceState(null, "", href);
    notify();
  }),
  back: vi.fn(() => window.history.back()),
  forward: vi.fn(() => window.history.forward()),
  refresh: vi.fn(),
  prefetch: vi.fn(),
};

function useSearchParams(): URLSearchParams {
  const search = useSyncExternalStore(subscribe, () => window.location.search, () => "");
  // 렌더마다 새 객체를 주면 searchParams 를 의존성으로 쓰는 훅이 매번 다시 돈다.
  return useMemo(() => new URLSearchParams(search), [search]);
}

function usePathname(): string {
  return useSyncExternalStore(subscribe, () => window.location.pathname, () => "/");
}

export const navigationModule = {
  useRouter: () => routerMock,
  useSearchParams,
  usePathname,
  notFound: vi.fn(),
  redirect: vi.fn(),
};

/**
 * 주소를 url 로 두고, 이 탭의 첫 화면 기록을 entry 로 맞춘다(null = 기록 없음).
 * 기본값은 "지금 화면이 첫 화면" — 링크로 바로 들어온 상태다.
 */
export function resetNavigation(url = "/", entry: string | null = url): void {
  window.history.replaceState(null, "", url);
  try {
    window.sessionStorage.clear();
    if (entry !== null) window.sessionStorage.setItem(ENTRY_KEY, entry);
  } catch {
    // 저장소를 막아 둔 테스트가 있다. 그 테스트가 스스로 되돌린다.
  }
  routerMock.push.mockClear();
  routerMock.replace.mockClear();
  routerMock.back.mockClear();
  routerMock.forward.mockClear();
  routerMock.refresh.mockClear();
  routerMock.prefetch.mockClear();
  notify();
}
```

```ts
 * 이 탭에서 앱에 처음 들어온 주소. 왼쪽 위 화살표가 "뒤로" 갈지 "정해 둔 상위 화면" 으로

export const ENTRY_KEY = "perky.entry";

/**
 * <head> 인라인 스크립트. 전체 로드 때마다 React 보다 먼저 돈다.
 *
 * - 이미 적혀 있으면 덮지 않는다. 새로고침해도 sessionStorage 와 브라우저 기록이 함께
 *   남으므로 판정이 그대로 유지된다.

 *   하고, 그 로드에서 /onboarding 이 적힌다.
 * - 저장소가 막혀 있으면 조용히 넘어간다. isEntryPage 가 그 경우를 첫 화면으로 본다.
 */
export const ENTRY_SCRIPT = `try{if(location.pathname!=="/"&&!sessionStorage.getItem("${ENTRY_KEY}")){sessionStorage.setItem("${ENTRY_KEY}",location.pathname+location.search)}}catch(e){}`;

/** 기록과 비교하는 형태의 지금 주소. 경로 + 쿼리(브라우저가 인코딩한 그대로). */
export function currentUrl(): string {
  return window.location.pathname + window.location.search;
}

/**
 * 지금 화면이 이 탭의 첫 화면인가.
 *
 * 기록이 없거나 저장소가 막혀 있으면 첫 화면으로 본다. history.back() 으로 앱 밖에
 * 튕기는 것보다 정해 둔 상위 화면으로 가는 편이 안전하다.
 */
export function isEntryPage(): boolean {
  try {
    const entry = window.sessionStorage.getItem(ENTRY_KEY);
    return entry === null || entry === currentUrl();
  } catch {
    return true;
  }
}

/**
 * replace 는 기록을 늘리지 않는다. 첫 화면에서 replace 하면 바뀐 주소가 여전히 첫 화면이라
 * 기록도 따라 옮긴다. 안 옮기면 /find → /find?q=birth 로 바뀐 순간 첫 화면을 잃고, 첫 질문의
 * 화살표가 history.back() 으로 앱 밖에 나간다.
 */
export function moveEntryOnReplace(to: string): void {
  try {
    if (window.sessionStorage.getItem(ENTRY_KEY) === currentUrl()) {
      window.sessionStorage.setItem(ENTRY_KEY, to);
    }
  } catch {
    // 저장소가 막혀 있으면 isEntryPage 가 늘 첫 화면으로 본다. 옮길 것이 없다.
  }
}
```

```ts
import { useCallback, useEffect } from "react";
import { usePathname, useRouter, useSearchParams } from "next/navigation";
import { isEntryPage, moveEntryOnReplace } from "./entry";

/**
 * 단계 주소와 뒤로가기 (docs/기획/2026-11-03-단계-이동-설계.md "이동 규칙").
 *
 * 질문 단계를 컴포넌트 상태가 아니라 주소(?q= / ?s= / ?g=)에 둔다. 그래야 "다음" 이
 * 브라우저 기록을 하나씩 쌓고, 휴대폰 뒤로가기가 이전 질문으로 간다. 상태에만 두면 기록에
 * 남지 않아 뒤로가기가 앱 밖으로 나간다.
 *
 * useStepParam 은 useSearchParams 를 쓴다. 정적 export 에서는 이 훅을 쓰는 화면의 본문을
 * <Suspense> 안에 둬야 빌드가 된다.
 */

/** 주소 값을 단계로 읽는다. 없거나, 모르는 값이거나, 앞 단계를 건너뛴 주소면 첫 미답 단계로 돌린다. */
export function resolveStep<K extends string>(
  raw: string | null,
  keys: readonly K[],
  firstUnanswered: K,
  isReachable: (k: K) => boolean
): { step: K; redirect: boolean } {
  const known = keys.find((k) => k === raw);
  if (known !== undefined && isReachable(known)) return { step: known, redirect: false };
  return { step: firstUnanswered, redirect: true };
}

/** 단계 주소. 다른 쿼리는 버리고, 그 단계에 필요한 값만 extra 로 다시 붙인다. */
export function stepHref(
  pathname: string,
  param: string,
  step: string,
  extra: Record<string, string> = {}
): string {
  return `${pathname}?${new URLSearchParams({ [param]: step, ...extra }).toString()}`;
}

/** replace 하면서 "이 탭의 첫 화면" 기록도 따라 옮긴다 (lib/entry.ts 의 moveEntryOnReplace). */
export function replaceKeepingEntry(router: { replace(href: string): void }, href: string): void {
  moveEntryOnReplace(href);
  router.replace(href);
}

export interface StepNavigation<K extends string> {
  /** 지금 단계. 주소에서 읽는다. */
  step: K;
  /** 단계 말고 주소에 있는 값 (예: /find 지역 질문의 p=<시도명>). */
  query(name: string): string | null;
  /** 다른 단계로 간다. 기록이 하나 쌓인다. */
  go(step: K, extra?: Record<string, string>): void;
}

export function useStepParam<K extends string>(
  param: string,
  keys: readonly K[],
  opts: {
    /** 저장된 답을 다 불러왔는가. 그 전에는 주소를 고치지 않는다 — 빈 답으로 판정하면 늘 첫 단계로 튕긴다. */
    ready: boolean;
    /** 주소에 단계가 없거나 갈 수 없는 단계일 때 보낼 곳. */
    firstUnanswered: K;
    /** 이 단계 앞의 답이 다 있는가. */
    isReachable(k: K): boolean;
  }
): StepNavigation<K> {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();
  const raw = searchParams.get(param);

  const { step, redirect } = opts.ready
    ? resolveStep(raw, keys, opts.firstUnanswered, opts.isReachable)
    : { step: keys.find((k) => k === raw) ?? opts.firstUnanswered, redirect: false };
  const target = stepHref(pathname, param, step);

  useEffect(() => {
    // replace — 기록을 늘리지 않는다. 주소에 단계가 없던 화면이 그대로 그 단계 화면이 된다.
    if (redirect) replaceKeepingEntry(router, target);
  }, [redirect, target, router]);

  const go = useCallback(
    (next: K, extra?: Record<string, string>) => router.push(stepHref(pathname, param, next, extra)),
    [router, pathname, param]
  );
  const query = useCallback((name: string) => searchParams.get(name), [searchParams]);

  return { step, query, go };
}

/**
 * 왼쪽 위 화살표 = 휴대폰 뒤로가기.
 *
 * 앞 화면이 이 앱 안이면 history.back(). 이 탭의 첫 화면이면 backHref 로 replace 하고 그
 * 자리를 새 첫 화면으로 삼는다. push 로 가면 backHref 화면의 화살표가 다시 history.back()
 * 으로 방금 떠난 화면에 돌아가 두 화면 사이를 오간다.
 */
export function useBack(backHref: string): () => void {
  const router = useRouter();
  return useCallback(() => {
    if (isEntryPage()) replaceKeepingEntry(router, backHref);
    else window.history.back();
  }, [router, backHref]);
}
```

```tsx
"use client";

import { useBack } from "@/lib/navigation";
import { ArrowLeft, ICON_LG } from "./icons";
import { IconButton } from "./IconButton";
import { HomeMark } from "./Wordmark";

/** 화면마다 8종이던 뒤로 문구를 하나로 모았다 (docs/기획/2026-11-03-단계-이동-설계.md). */
const BACK_LABEL = "이전 단계로";

/**
 * 모든 내부 화면의 상단 바. 뒤로가기 + 브랜드.
 *
 * 화살표는 휴대폰 뒤로가기와 같다(lib/navigation.ts 의 useBack). 앞 화면이 이 앱 안이면
 * history.back(), 이 탭에서 처음 들어온 화면이면 backHref 로 간다 — 목록·결과 화면은 링크로
 * 바로 들어올 수 있어서 앞 화면이 앱 밖일 수 있다. 예전에는 화살표가 backHref 로 새로
 * 이동해 기록이 쌓였고, 그 뒤 휴대폰 뒤로가기가 방금 떠난 화면으로 되돌아갔다.
 *
 * 오른쪽 자리는 비어 있어도 폭을 잡는다. 그래야 가운데 브랜드가 화면 중앙에 온다.
 *
 * 배경이 canvas 인 이유: sticky 로 붙었을 때 아래 본문이 비쳐 지나가면 안 된다.
 */
export function TopBar({
  backHref,
  right,
}: {
  /** 앞 화면이 앱 밖일 때 갈 곳. 없으면 화살표를 그리지 않는다. */
  backHref?: string;
  /**
   * @deprecated 문구는 "이전 단계로" 하나다. app/result/ResultState.tsx(손대지 않는 파일)가
   * 아직 넘기므로 받기만 하고 쓰지 않는다.
   */
  backLabel?: string;
  right?: React.ReactNode;
}) {
  return (
    /* 44px 버튼 안 24px 아이콘의 좌우 여백은 10px이다. 헤더 패딩을 320px에서
       6px, 390px 이상에서 10px로 주면 아이콘 끝이 각 본문 gutter(16/20px)에 맞는다. */
    <header className="sticky top-0 z-20 -mx-4 bg-canvas px-1.5 pt-[env(safe-area-inset-top)] min-[390px]:-mx-5 min-[390px]:px-2.5">
      <div className="flex h-14 items-center justify-between">
        {backHref ? <BackButton backHref={backHref} /> : <span className="w-11" aria-hidden="true" />}

        <HomeMark />

        {right ?? <span className="w-11" aria-hidden="true" />}
      </div>
    </header>
  );
}

/** 훅은 조건부로 부를 수 없어서 화살표를 따로 뺐다. backHref 가 있을 때만 그린다. */
function BackButton({ backHref }: { backHref: string }) {
  const back = useBack(backHref);
  return (
    <IconButton label={BACK_LABEL} onClick={back}>
      <ArrowLeft size={ICON_LG} aria-hidden="true" />
    </IconButton>
  );
}
```

```tsx
 * 예전에는 여러 질문을 테두리 친 카드로 한 화면에 쌓았다. 답한 것과 안 한 것이

 *

const brackets = bracketsJson as IncomeBracket[];
const policies = policiesJson as PolicyMeta[];
const STATUSES: DiscoveryStatus[] = ["대학생", "재직", "구직"];
/**

const HOUSING_TYPES: { value: HousingType; label: string }[] = [

const QUESTIONS = [
  { key: "birthDate", step: "birth", label: "생년월일", title: "생년월일이 어떻게 되시나요?" },
  { key: "region", step: "region", label: "사는 곳", title: "어디에 살거나 살 예정인가요?" },
  { key: "status", step: "status", label: "현재 상태", title: "현재 상태가 어떻게 되시나요?" },
  { key: "incomeBracket", step: "income", label: "월 소득", title: "본인의 월 소득은 어느 정도인가요?" },
  { key: "housingType", step: "housing", label: "주거 형태", title: "현재 어떤 형태로 거주하고 있나요?" },
] as const satisfies readonly { key: AnsweredKey; step: string; label: string; title: string }[];

type FindStep = (typeof QUESTIONS)[number]["step"];
const STEP_KEYS: readonly FindStep[] = QUESTIONS.map((q) => q.step);

/** 쌓인 줄과 요약 칩이 같은 어휘를 쓰도록 지역 라벨은 REGION_OPTIONS 에서만 온다. */
const regionLabel = (value: string | null) =>
  REGION_OPTIONS.find((o) => o.value === value)?.chipLabel ?? null;

const bracketLabel = (bracket: number | null) =>
  brackets.find((b) => b.bracket === bracket)?.label ?? null;

/** 저장된 생년월일을 사람이 읽는 형태로. 나이는 기준일이 있어야 하므로 따로 붙인다. */
function birthDateLabel(birthDate: string | null, age: number | null): string | null {
  const parts = birthDate === null ? null : fromISODate(birthDate);
  if (!parts) return null;
  const 날짜 = `${parts.year}년 ${parts.month}월 ${parts.day}일`;
  return age === null ? 날짜 : `${날짜} · 만 ${age}세`;
}

/** useSearchParams 를 쓰므로 정적 export 에서 본문을 Suspense 안에 둔다. 경계 밖 HTML 은 불러오는 중 화면이다. */

function FindSteps() {
  const router = useRouter();
  const [answers, setAnswers] = useState<DiscoveryAnswers>(EMPTY_ANSWERS);
  // 정적 빌드 시점의 날짜가 HTML 에 박히면 안 되므로 브라우저에서 채운다.
  const [asOf, setAsOf] = useState<string | undefined>(undefined);
  const [loaded, setLoaded] = useState(false);
  /**
   * 실제로 답한 질문. 예전 저장값을 안전하게 정리하면서도 완료한 순서를 유지한다.
   * (lib/storage.ts의 loadAnsweredKeys 주석 참고).
   */
  const [answered, setAnswered] = useState<AnsweredKey[]>([]);

  // 서버 렌더링 후 브라우저에서 저장된 답변을 불러온다.
  useEffect(() => {
    const loadedAnswers = loadAnswers();
    // 예전의 '그 외 지역'·'전북(익산 외)'·모름 저장값은 현재 시군구 답이 아니다.
    // 그대로 통과시키면 사용자가 새 선택지를 보지도 않고 예전의 넓은 지역으로 판정된다.
    const saved = {
      ...loadedAnswers,
      region:
        loadedAnswers.region && isRegionValue(loadedAnswers.region)
          ? loadedAnswers.region
          : null,
    };
    const savedKeys = loadAnsweredKeys().filter((key) => saved[key] !== null);
    setAnswers(saved);
    setAnswered(savedKeys);
    if (saved.region !== loadedAnswers.region) saveAnswers(saved);
    saveAnsweredKeys(savedKeys);
    setAsOf(todayISO());
    setLoaded(true);
  }, []);

  // 주소에 단계가 없으면 첫 미답 질문으로, 다 답했으면 마지막 질문으로 replace 한다.
  // 마지막 단계에는 앞선 네 답이 다 보여서 그 자체가 답변 요약이자 수정 진입점이 된다.
  const 미답 = QUESTIONS.findIndex((q) => !answered.includes(q.key));
  const { step: stepKey, query, go } = useStepParam("q", STEP_KEYS, {
    ready: loaded,
    firstUnanswered: QUESTIONS[미답 === -1 ? QUESTIONS.length - 1 : 미답].step,
    // 앞 질문을 건너뛴 주소(예: 생년월일 없이 ?q=income)로는 들어올 수 없다.
    isReachable: (k) =>
      QUESTIONS.slice(0, STEP_KEYS.indexOf(k)).every((q) => answered.includes(q.key)),
  });
  const step = STEP_KEYS.indexOf(stepKey);
  /** 지역 질문 안에서 먼저 고른 시·도. 주소(p)에 있어서 뒤로가기가 시·도 목록으로 돌아온다. */
  const province =
    step === 1 ? (REGION_HIERARCHY.find((item) => item.name === query("p")) ?? null) : null;
  /** 이미 답한 시·군·구의 시·도. 시·도 목록에서 그 카드를 선택된 것으로 보여준다. */
  const answeredProvince = provinceForRegion(answers.region);

  function update(key: AnsweredKey, patch: Partial<DiscoveryAnswers>) {
    const next = { ...answers, ...patch };
    setAnswers(next);
    saveAnswers(next);

    if (!answered.includes(key)) {
      const nextKeys = [...answered, key];
      setAnswered(nextKeys);
      saveAnsweredKeys(nextKeys);
    }
  }

  // 판정 코드는 나이만 본다. 생년월일 → 만 나이 변환은 여기 한 곳에서만 한다.
  const resolved = resolveAnswers(answers, asOf ?? null);
  const groups = groupPolicies(policies, resolved);
  const count = candidateCount(groups);
  // Find에서는 모든 질문을 실제 값으로 답해야 하므로 요약에 '모름'을 만들지 않는다.
  const 답변줄 = [
    birthDateLabel(answers.birthDate, resolved.age),
    regionLabel(answers.region),
    answers.status,
    bracketLabel(answers.incomeBracket),
    answers.housingType,
  ];

  /** 지금 질문보다 앞선 것 중 답한 것만, 가장 최근에 답한 것이 위로 오게 쌓는다. */
  const 쌓인답 = QUESTIONS.slice(0, step)
    .map((q, i) => ({
      label: q.label,
      value: answered.includes(q.key) ? 답변줄[i] : null,
      onEdit: () =>
        go(q.step, q.key === "region" && answeredProvince ? { p: answeredProvince.name } : undefined),
    }))
    .reverse();

  const isLast = step === QUESTIONS.length - 1;
  const currentKey = QUESTIONS[step].key;
  // 시·도 목록에서는 이미 답한 지역이 있으면 그대로 넘어갈 수 있다. 다른 시·도의 시·군·구
  // 목록을 연 상태에서는 그 안에서 새로 골라야 한다.
  const hasCurrentAnswer =
    answered.includes(currentKey) &&
    answers[currentKey] !== null &&
    (currentKey !== "region" || province === null || answeredProvince?.name === province.name);

  function handleNext() {
    if (!hasCurrentAnswer) return;
    // 마지막 답을 하면 결과 요약으로. 목록은 그 다음이다.
    if (isLast) return router.push("/find/result");
    go(QUESTIONS[step + 1].step);
  }

  if (!loaded) return <FindLoading />;

  const current = QUESTIONS[step];
  const heading =
    step === 1
      ? province
        ? `${province.name}의 시·군·구를 선택해주세요`
        : "먼저 시·도를 선택해주세요"
      : current.title;

  return (
    <AppShell>
      <TopBar backHref="/" />

      <main key={`${stepKey}-${province?.name ?? ""}`} className="step-in flex flex-1 flex-col gap-7 pb-8 pt-7">
        <StepHeader title={heading} />

        {step === 0 && (
          <div className="flex flex-col gap-3">
            <WheelDatePicker
              label="생년월일"
              years={birthYearOptions(new Date().getFullYear())}
```

- [ ] **Step 4: `regionDisplayName`** — `lib/region.ts` 파일 끝에

```ts
/**
 * 여러 시·도에 같은 이름이 있는 시·군·구 (중구·동구·서구·남구·북구·강서구·고성군).
 * 손으로 적지 않고 REGION_HIERARCHY 에서 센다 — 시군구가 늘면 같이 늘어난다.
 */
export const DUPLICATE_DISTRICT_NAMES: ReadonlySet<string> = (() => {
  const counts = new Map<string, number>();
  for (const province of REGION_HIERARCHY) {
    for (const district of province.districts) {
      counts.set(district.chipLabel, (counts.get(district.chipLabel) ?? 0) + 1);
    }
  }
  return new Set([...counts].filter(([, n]) => n > 1).map(([name]) => name));
})();

/**
 * 답 요약에 쓰는 짧은 지역 이름. "익산시" 처럼 시·군·구 이름만 쓰되, 여러 시·도에 겹치는
 * 이름이면 "부산 중구" 처럼 시·도 약칭(REGION_HIERARCHY 의 chipLabel)을 붙인다. 모르는 값은
 * 그대로 돌려준다.
 */
export function regionDisplayName(region: string): string {
  const province = provinceForRegion(region);
  const district = province?.districts.find((d) => d.value === region);
  if (!province || !district) return region;
  return DUPLICATE_DISTRICT_NAMES.has(district.chipLabel)
    ? `${province.chipLabel} ${district.chipLabel}`
    : district.chipLabel;
}
```

```tsx
 * lead 는 왼쪽 앞의 고정 자리다 — /eligibility 의 진행 표시("2/3 가구 · 소득").
 * 항목도 lead 도 없으면 아무것도 그리지 않는다.
 *
 * 상단바(TopBar)는 h-14 + safe-area 높이로 sticky top-0 이다. 이 줄은 그 바로 아래에
 * 붙고 z 는 상단바보다 낮다.
 */
export function AnswerSummaryBar({
  items,
  lead,
}: {
  items: SummaryItem[];
  lead?: React.ReactNode;
}) {
  const router = useRouter();
  if (items.length === 0 && !lead) return null;

  return (
    <nav
      aria-label="고른 답"
      className="sticky top-[calc(3.5rem+env(safe-area-inset-top))] z-10 -mx-4 flex items-center gap-2 bg-canvas px-4 min-[390px]:-mx-5 min-[390px]:px-5"
    >
      {lead && <div className="shrink-0">{lead}</div>}
      {lead && items.length > 0 && <span aria-hidden="true" className="h-4 w-px shrink-0 bg-ink-200" />}
      {items.length > 0 && (
        <ol className="no-scrollbar flex min-w-0 flex-1 items-center overflow-x-auto whitespace-nowrap">
          {items.map((item, i) => (
            <li key={item.key} className="flex shrink-0 items-center">
              {i > 0 && (
                <span aria-hidden="true" className="px-0.5 text-ink-300">
                  ·
                </span>
              )}
              <a
                href={item.href}
                aria-label={`${item.label} 고치기: ${item.value}`}
                onClick={(e) => {
                  e.preventDefault();
                  router.push(item.href);
                }}
                className="focus-ring inline-flex min-h-11 items-center rounded-control px-1.5 text-sm font-semibold text-ink-700 transition-colors hover:bg-brand-50 hover:text-brand-800"
              >
                {item.value}
              </a>
            </li>
          ))}
        </ol>
      )}
    </nav>
  );
}
```

```tsx
   behavior 는 별개라 여기서 직접 물어본다 (WheelDatePicker 와 같은 방법). */
function prefersReducedMotion(): boolean {
  return (

function answerText(question: QuestionDef, value: unknown): string {
  if (value === "unknown" || value === "" || value === undefined) return "모름";
  if (question.type === "boolean") return value === true ? "그렇다" : "아니다";
  if (question.type === "date" && typeof value === "string") return formatDotDate(value);
  if (question.type === "number" && typeof value === "number") {
    return question.money ? formatKoreanMoney(value) : String(value);
  }
  if (question.type === "select") {
    return question.options?.find((o) => o.value === value)?.label ?? String(value);
  }
  return String(value);
}

          </span>
        }
        items={summary}
      />

      <main key={stepKey} className="step-in flex flex-1 flex-col gap-8 py-7">
        <StepHeader title={current.heading} />

        {current.questions.map((q) => (
          <QuestionField
            key={q.key}
            question={q}
            value={profile[q.key]}
            folded={folded.has(q.key)}
            onChange={(v) => answer(q, v, current.questions)}
            onUnfold={() => unfold(q.key)}
            fieldRef={(el) => {
              if (el) fieldRefs.current.set(q.key, el);
              else fieldRefs.current.delete(q.key);
            }}
            titleRef={(el) => {
              if (el) titleRefs.current.set(q.key, el);
              else titleRefs.current.delete(q.key);
            }}
          />
        ))}

        {error && <FieldError>{error}</FieldError>}
      </main>

      <StickyBottomAction>
        <Button onClick={handleNext}>{isLast ? "결과 확인하기" : "다음"}</Button>
      </StickyBottomAction>
    </AppShell>
  );
}

function QuestionField({
  question,
  value,
  folded,
  onChange,
  onUnfold,
  fieldRef,
  titleRef,
}: {
  question: QuestionDef;
  value: unknown;
  folded: boolean;
  onChange: (value: unknown) => void;
  onUnfold: () => void;
  fieldRef: (el: HTMLDivElement | null) => void;
  titleRef: (el: HTMLLabelElement | null) => void;
}) {
  const isUnknown = value === "unknown";
  // 라벨을 for/id 로 묶는다. 묶이지 않으면 스크린리더가 입력칸을 이름 없이 읽고,
  // 라벨을 눌러도 칸에 포커스가 가지 않는다.
  const inputId = `q-${question.key}`;

  if (folded) {
    const text = answerText(question, value);
    return (
      <div ref={fieldRef}>
        <button
          type="button"
          onClick={onUnfold}
          aria-label={`${question.shortLabel} 고치기: ${text}`}
          className="focus-ring flex min-h-11 w-full items-center justify-between gap-3 rounded-control bg-surface px-4 py-2.5 text-left shadow-card transition-colors hover:bg-brand-50"
        >
          <span className="min-w-0 truncate text-sm">
            <span className="font-semibold text-ink-500">{question.shortLabel}</span>
            <span aria-hidden="true" className="px-1.5 text-ink-300">
              ·
            </span>
            <span className="font-bold text-ink-900">{text}</span>
          </span>
          <Pencil size={ICON_SM} aria-hidden="true" className="shrink-0 text-ink-300" />
        </button>
      </div>
    );
  }

  return (
    <div ref={fieldRef} className="flex flex-col gap-3">
      {/* tabIndex -1: 미답으로 "다음" 을 누르면 여기로 포커스를 옮긴다. 탭 순서에는 넣지 않는다. */}
      <label
        ref={titleRef}
        htmlFor={inputId}
        tabIndex={-1}
        className="rounded-control text-base font-bold leading-snug text-ink-900 outline-none focus:ring-4 focus:ring-brand-100"
      >
        {question.label}
      </label>

      {/* 생년월일 — 계약 시작 예정일과 같은 휠 피커를 쓴다. 앱 안에 날짜 UI 가
          두 종류이면 같은 동작을 두 번 배워야 한다.
          연도는 최신 생년(만 18세)이 맨 위다. <input type="date"> 는 오늘(2026)부터
          시작해서 청년이 19년을 거슬러 올라가야 했다. */}
      {question.type === "date" && (
        <WheelDatePicker
          id={inputId}
          label={question.label}
          years={birthYearOptions(new Date().getFullYear())}
          value={typeof value === "string" ? value : ""}
          onChange={(v) => onChange(v)}
        />
      )}

      {question.type === "boolean" && (
        <div className="flex flex-col gap-2">
          <ChoiceCard active={value === true} onClick={() => onChange(true)}>
            그렇다
          </ChoiceCard>
          <ChoiceCard active={value === false} onClick={() => onChange(false)}>
            아니다
          </ChoiceCard>
          {question.allowUnknown && (
            <ChoiceCard active={isUnknown} onClick={() => onChange("unknown")}>
              모름
            </ChoiceCard>
          )}
        </div>
      )}

      {/* 빈 칸 = 모름이다. 예전에는 '모름' 을 두 번 누르면 값이 0 이 됐고, 소득 0원은
          모든 소득 상한을 통과해 '예상 적용' 으로 잘못 판정됐다. 칸을 비활성화하지
          않으므로 숫자를 입력하면 모름이 자연스럽게 풀린다. */}
      {question.type === "number" && (
        <div className="flex flex-col gap-2">
          {/* 빈 칸 = 모름이다. MoneyInput 은 0 하나 더/덜 친 실수를 그 자리에서
              읽어준다 (F1-8). 금액이 아닌 숫자(가구원 수)는 환산이 없다. */}
          {question.money ? (
            <MoneyInput
              id={inputId}
              value={typeof value === "number" ? value : null}
              onChange={(won) => onChange(won === null ? "unknown" : won)}
            />
          ) : (
            <NumberInput
              id={inputId}
              value={typeof value === "number" ? value : null}
              onChange={(v) => onChange(v === null ? "unknown" : v)}
            />
          )}
          {question.allowUnknown && (
            <ChoiceCard active={isUnknown} onClick={() => onChange("unknown")}>
              모름
            </ChoiceCard>
          )}
        </div>
      )}

      {question.type === "select" && (
        <select
          id={inputId}
          className="input"
          value={typeof value === "string" ? value : "unknown"}
          onChange={(e) => onChange(e.target.value)}
        >
          {question.options?.map((opt) => (
            <option key={opt.value} value={opt.value}>
              {opt.label}
            </option>
          ))}
          {question.allowUnknown && <option value="unknown">모름</option>}
        </select>
      )}
    </div>
  );
}
```

```js
import { readFile } from "node:fs/promises";
import { existsSync } from "node:fs";
import { extname, join, normalize } from "node:path";
import { chromium } from "playwright";

const ROOT = new URL("../out/", import.meta.url).pathname;
const PORT = 4322; // shoot.mjs(4321)와 동시에 돌려도 부딪히지 않게

const MIME = {
  ".html": "text/html; charset=utf-8",
  ".js": "text/javascript",
  ".css": "text/css",
  ".json": "application/json",
  ".webp": "image/webp",

/** 정적 export 는 `/find` 를 `find.html` 로 굽는다. 후보를 차례로 시도한다 (shoot.mjs 와 같다). */
async function resolve(pathname) {
  const clean = normalize(decodeURIComponent(pathname)).replace(/^(\.\.[/\\])+/, "");
  for (const candidate of [clean, `${clean}.html`, join(clean, "index.html")]) {
    const file = join(ROOT, candidate);
    if (!file.startsWith(ROOT)) continue;
    if (existsSync(file) && extname(file)) return file;
  }
  return null;
}

const server = createServer(async (req, res) => {
  const { pathname } = new URL(req.url, "http://x");
  if (pathname === OUTSIDE) {
    res.writeHead(200, { "content-type": "text/html; charset=utf-8" });
    res.end('<!doctype html><meta charset="utf-8"><title>앱 밖</title><p>앱 밖</p>');
    return;
  }
  const file = await resolve(pathname);
  if (!file) {
    res.writeHead(404).end("not found");
    return;
  }
  res.writeHead(200, { "content-type": MIME[extname(file)] ?? "application/octet-stream" });
  res.end(await readFile(file));
});

/** 지금 어디인가. 질문 화면은 단계 주소까지, 그 밖은 경로만. */
function where(page) {
  const url = new URL(page.url());
  if (url.origin !== ORIGIN || url.pathname === OUTSIDE) return "앱 밖";
  const q = url.searchParams.get("q");
  if (!q) return url.pathname;
  const p = url.searchParams.get("p");
  return `${url.pathname}?q=${q}${p ? `&p=${p}` : ""}`;
}

/** 클라이언트 이동(push·replace·popstate)이 화면에 반영될 때까지. */
async function settle(page) {
  await page.waitForLoadState("networkidle");
  await page.waitForTimeout(300);
}

async function press(page, name) {
  await page.getByRole("button", { name, exact: true }).click();
  await settle(page);
}

const arrow = (page) => press(page, "이전 단계로");

async function browserBack(page) {
  await page.goBack();
  await settle(page);
}

/** 처음 접속 → 온보딩 3장 → /find?q=birth */
async function enter(browser) {
  const context = await browser.newContext({
    viewport: { width: 390, height: 844 },
    reducedMotion: "reduce",
    locale: "ko-KR",
  });
  const page = await context.newPage();
  await page.goto(ORIGIN + OUTSIDE);
  // layout 의 <head> 스크립트가 "/" 를 /onboarding 으로 location.replace 한다.
  await page.goto(`${ORIGIN}/`, { waitUntil: "commit" });
  await page.waitForURL("**/onboarding", { waitUntil: "networkidle" });
  await settle(page);
  await press(page, "다음");
  await press(page, "다음");
  await press(page, "내 혜택 찾아보기");
  await page.waitForURL(/\/find\?q=birth$/);
  await settle(page);
  return { context, page };
}

/** 질문에 차례로 답한다. stopAt 이 "status" 면 현재 상태 질문에서 멈춘다. 아니면 /find/result 까지. */
async function answer(page, stopAt) {
  // 아직 안 고른 사람에게는 휠이 펼쳐져 있다. '확인' 은 휠이 가리키는 날짜(만 18세 생일)를 올린다.
  await press(page, "확인");
  await press(page, "다음"); // ?q=region
  await press(page, "전북특별자치도"); // ?q=region&p=전북특별자치도
  await press(page, "익산시");
  await press(page, "다음"); // ?q=status
  if (stopAt === "status") return;
  await press(page, "대학생");
  await press(page, "다음"); // ?q=income
  await press(page, "월 100만원 이하");
  await press(page, "다음"); // ?q=housing
  await press(page, "월세");
  await press(page, "다음");
  await page.waitForURL("**/find/result");
  await settle(page);
}
```

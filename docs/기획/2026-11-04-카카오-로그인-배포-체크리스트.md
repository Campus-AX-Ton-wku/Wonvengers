|---|---|---|
| 연결 끊기 요청 | `POST https://kapi.kakao.com/v1/user/unlink`, `Authorization: KakaoAK {Admin 키}`, `target_id_type=user_id&target_id={회원번호}` | 일치 (2026-11-04) |

| 탈퇴 시 연결 끊기 의무 | 탈퇴 때 항상 끊는다 | 의무다 (2026-11-04) — "카카오 로그인으로 서비스를 이용 중이던 사용자가 서비스에서 탈퇴 또는 카카오 로그인 연동 해제를 요청하면, 서비스는 반드시 탈퇴 과정에 연결 해제 요청을 포함해 앱과 사용자의 연결을 끊어야 합니다." |

확인한 문서 (2026-11-04):

- 연결 끊기 요청 — <https://developers.kakao.com/docs/latest/ko/kakaologin/rest-api#unlink>
  (지금은 `https://developers.kakao.com/docs/ko/kakaologin/rest-api` 로 넘어간다). "요청: 서비스 앱 어드민 키 방식"
  헤더 `Authorization: KakaoAK ${SERVICE_APP_ADMIN_KEY}`, `Content-Type` 은 form-urlencoded(UTF-8),
  본문 `target_id_type`(`user_id` 고정)·`target_id`(회원번호, Long) 모두 필수.
- 오류 코드 — <https://developers.kakao.com/docs/latest/ko/rest-api/reference#response-code> 는 오류 코드 목록을
  <https://developers.kakao.com/docs/ko/rest-api/error-code> 로 안내한다. 그 표: "`-101` · 400 · 해당 앱에 카카오계정
  연결이 완료되지 않은 사용자가 호출한 경우". 연결 끊기 문서 자체에는 `-101` 이 따로 적혀 있지 않다 — 공통 오류 코드표의
  뜻(앱에 연결되지 않은 사용자)이 "이미 끊김"과 같아 성공으로 본다.
- 탈퇴 의무 — <https://developers.kakao.com/docs/ko/kakaologin/common> "회원 탈퇴 › 서비스의 탈퇴 절차" (위 따옴표 문구).
  같은 문서는 서비스 밖에서 끊긴 경우(연결된 서비스 관리·카카오계정 탈퇴)를 알도록 연결 끊기 웹훅을 두라고 권한다 —
  이번 설계에는 없다(밖에서 끊어도 우리 DB 항목은 TTL 1년 전까지 남는다). 넣을지 사용자에게 확인이 필요하다.

## 3. 체크리스트

### 배포 전
- [ ] 1절 카카오 문서 재확인이 "일치"
- [ ] SSM `/perky/kakao/client-id`(String)·`client-secret`·`admin-key`(SecureString) 있음 — 값은 출력하지 않는다. SecureString 은 기본 키(`aws/ssm`)로 만든다(Lambda 에 KMS 권한을 주지 않았다)
- [ ] Cognito 도메인 접두어 `perky-wonvengers` 를 쓸 수 있는지(다른 계정이 쓰고 있지 않은지) 확인. 막혀 있으면 접두어를 바꾸고 아래 Redirect URI 도 같이 바꾼다
- [ ] 이름 고정 자원 `perky-user-data`(테이블)·`perky-users`(User Pool)는 `RETAIN` 이라 `cdk destroy` 뒤에도 남아 같은 이름으로 다시 만들 수 없다 — 재배포가 필요하면 먼저 남은 자원을 정리(저장된 답의 파기와 함께 결정)
- [x] 세 패키지 테스트 통과: `apps/web`·`apps/api`·`infra` 에서 `node node_modules/vitest/vitest.mjs run` — 2026-11-08 web 754 · api 52 · infra 18
- [ ] `infra` 에서 `npx cdk diff PerkyStack --profile perky` 를 사용자와 함께 확인 (Organizations·IAM Identity Center 자원 없음 — 어떤 경우에도 켜지 않는다)
- [ ] 무료 플랜 종료(2027-01-02) 전 유료 전환 여부 결정. 전환 전에 Lambda·DynamoDB·Cognito Lite 공식 무료 사용량을 다시 확인. 전환해도 Organizations·Identity Center 는 켜지 않는다

### 배포
- [ ] `cdk deploy` (구현 계획 Task 3 Step 5 명령 — client secret 은 SSM 에서 읽어 `--parameters` 로)
- [ ] 카카오 콘솔 [앱] > [플랫폼 키] > REST API 키 의 Redirect URI 를 시험용(spike) 주소에서 `https://perky-wonvengers.auth.ap-northeast-2.amazoncognito.com/oauth2/idpresponse` 로 바꾼다 (`KakaoRedirectUri` 출력값과 같은지 대조)
- [ ] Vercel 프로젝트 환경변수 — **Production 에만** `NEXT_PUBLIC_COGNITO_DOMAIN`·`NEXT_PUBLIC_COGNITO_CLIENT_ID`·`NEXT_PUBLIC_API_URL`. Preview 에는 넣지 않는다(미리보기 주소는 콜백 허용 목록에 없어 로그인이 실패한다). 넣은 뒤 다시 배포
- [ ] 배포된 HTML 에 CSP 가 있다: `curl -s https://wonvengers.vercel.app/find | grep -o 'connect-src[^;]*'` → Cognito 도메인과 API 출처가 보인다
- [ ] 호스팅이 허용하면 CSP 와 `frame-ancestors 'none'` 을 HTTP 헤더로도 건다(`vercel.json` `headers`). `<meta>` CSP 는 `frame-ancestors` 를 지원하지 않는다. 주의: CSP 헤더는 Vercel 미리보기 도구 모음(`vercel.live`)을 막는다 — 미리보기에서 도구 모음이 안 보여도 정상

### 배포 뒤
- [x] 실제 카카오 계정으로 회원 탈퇴를 한 번 해 보고 연결 끊기가 **200** 을 돌려주는지 확인(Lambda 로그). `-101` 은 성공으로 보기 때문에 Admin 키를 잘못 넣어도 가려질 수 있다 — 200 을 직접 봐야 한다
  - 2026-11-08: Lambda 로그는 경로 결과만 남겨(`DELETE /me` 204) 카카오 응답이 200 인지 `-101` 인지 구분되지 않는다. 대신 카카오 쪽에서 확인했다 — 연결된 서비스 관리에서 앱이 사라졌고, 다시 로그인할 때 카카오 동의 화면이 다시 나왔다(연결이 실제로 끊겼다). 후속: 연결 끊기 결과(`unlinked`/`already`)를 로그에 남기기
- [x] 두 브라우저 이어 보기·처음부터 다시·탈퇴 시험 (4절) — 결과는 5절
- [ ] 시험용 Cognito `perky-spike` 삭제 (위 시험들이 끝난 뒤), 카카오 Redirect URI 에서 spike 주소 삭제
- [ ] 처리방침 초안(`/privacy`) 팀·학교 검토 — 확인 필요 항목: 개인정보 보호책임자, 문의 방법, 시행일, 웹사이트 전송 업체(Vercel)의 국외 이전 해당 여부
- [ ] 카카오 연결 끊기 웹훅 — 넣을지 결정 (없으면 카카오 쪽에서 끊은 사람의 답이 마지막 저장 후 1년까지 남는다)
- [ ] 카카오 버튼 문구("카카오로 계속하기")가 카카오 디자인 가이드에 맞는지

### 되돌리기
- 프론트: Vercel 환경변수 세 개를 지우고 다시 배포하면 로그인 UI 가 사라지고 앱은 로그인 전과 똑같다
- 서버: `npx cdk destroy PerkyStack --profile perky`. User Pool·테이블은 `RETAIN` + 삭제 보호라 남는다 — 지우려면 삭제 보호를 끄고 따로 지운다(저장된 답의 파기와 함께 정한다)

## 4. 배포 뒤 시험 순서

1. 브라우저 A 에서 답을 고르고 카카오로 로그인 → 저장 동의 → 브라우저 B 에서 로그인해 같은 답이 보이는지
2. B 에서 '처음부터 다시' → A 를 새로고침해도 답이 비어 있는지
3. 로그아웃 → 이 기기의 사본이 지워졌는지
4. 회원 탈퇴 → 다시 로그인하면 새 계정처럼 동의부터 시작하는지, 카카오 연결이 끊겼는지(위 200 확인과 함께)

로컬 `npm run dev`(`http://localhost:3000`) + 정식 스택. 기기 A = 크롬, 기기 B = 엣지. 서버 쪽은 DynamoDB 항목 수·Cognito 사용자 수를 15초마다 확인했다.

| 2 | 서버 항목 1개 | 통과 — 12:45 사용자 1 → 항목 1 |

| 9 | 재로그인 시 새 회원·동의 화면 | 통과 — 카카오 동의 화면이 다시 나왔고, 13:35 새 회원으로 저장 |

함께 본 것:

- 13:22 `PUT /me/data` 409 → `GET` → `PUT` 200 — 두 기기에서 거의 동시에 고쳤을 때 충돌을 받아 다시 저장하는 경로가 실제로 돌았다.
- 카카오 로그인 화면(계정 확인)이 A 에서 나오지 않은 건 정상이다. A 크롬에 카카오 로그인 상태가 남아 있었고 같은 앱에 이미 동의한 계정이었다. 시연 녹화는 카카오에 로그인돼 있지 않은 게스트 창에서 할 것.
- A 크롬 콘솔의 hydration 오류 2건(`style="user-select:auto"`)은 브라우저 확장이 넣은 속성이다 — 코드·빌드 결과물에 없고, 확장이 없는 엣지에서는 나오지 않았다.

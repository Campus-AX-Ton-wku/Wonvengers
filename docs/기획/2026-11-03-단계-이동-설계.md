# 단계 이동 설계 — 뒤로가기, 버튼 일관성, 고른 답 보이기

작성일 2026-11-03 · 대상 `/find`, `/calculate`, `/eligibility`, `TopBar`, 화면별 하단 버튼

## 왜

1차 멘토링(2026-10-23)의 UI 지시는 세 가지였다.

1. 선택한 항목 강조와 지나온 기록(히스토리)
2. 이전·다음과 왼쪽 위 버튼의 일관성
3. 항목을 고르면 아래로 내려가는데 위에서 고른 내용이 보이지 않는다 — 뒤로가기 필요, 선택한 항목 노출 필요

2026-11-03 에 브라우저로 재현한 결과(처음 접속 → 온보딩 → 질문 5개 → 결과):

| 동작 | 지금 | 기대 |
|---|---|---|
| A. 질문 도중 휴대폰·브라우저 뒤로가기 | 이전 질문이 아니라 앱 밖(또는 온보딩 1장)으로 나간다 | 이전 질문 |
| B. 결과 화면에서 브라우저 뒤로가기 두 번 | 1번째는 거주 형태, 2번째는 바로 앱 밖 | 질문을 하나씩 거슬러 올라감 |
| C. 결과에서 왼쪽 위 화살표로 돌아간 뒤 브라우저 뒤로가기 | 방금 떠난 결과 화면으로 다시 간다 | 질문 이전 화면 |

원인은 두 가지다.

- 질문 단계가 컴포넌트 상태(`useState(step)`)에만 있어 브라우저 기록에 남지 않는다
- 왼쪽 위 화살표가 "뒤로"가 아니라 정해진 화면으로 새로 이동(`router.push`/`Link`)해 기록이 쌓인다

그 밖에 확인한 것(2026-11-03 코드 조사):

- 뒤로 버튼 방식이 `onBack`(함수)·`backHref`(링크) 두 가지로 섞이고, 문구가 8종이다
- 상단 화살표와 하단 버튼이 같은 곳으로 가는 화면이 3곳이다(`RequirementReview` "결과로 돌아가기", 정책 상세 "다른 혜택 보기", `/result` 하단과 상단)
- `/find` 는 답한 것을 현재 질문 **아래**에 쌓는다. 시군구·소득처럼 목록이 긴 단계에서는 화면 밖으로 밀린다
- `/eligibility` 는 한 화면에 질문 4~6개를 쌓고, 진행 표시·답 요약이 없으며, 미답 오류를 하단 한 줄로만 알린다
- 온보딩 문구가 질문을 "네 가지"라고 하지만 실제로는 5개다

## 결정 사항

| 질문 | 결정 |
|---|---|
| 범위 | 세 가지 모두, 1층(`/find`)과 2층(`/calculate`·`/eligibility`) 전부 |
| 고른 답 위치 | 상단바 아래 고정 한 줄. 아래에 쌓던 목록은 없앤다 |
| 왼쪽 위 화살표 | 휴대폰 뒤로가기와 같게. 앞 화면이 앱 밖이면 정해 둔 상위 화면으로 |
| `/eligibility` | 3개 묶음 유지 + 진행 표시·답 접기·자동 스크롤 |
| 단계 기록 방식 | 주소에 단계를 넣는다(접근 A) |

접근 B(주소는 그대로 두고 `history.pushState` 를 직접 조작)는 Next 라우터의 기록 관리와 부딪히기 쉽고,
새로고침하면 단계가 사라져 택하지 않았다.

### 2026-08-30 화면 구조 개편 설계에서 바꾸는 것

멘토 피드백으로 아래 세 결정을 뒤집는다. 그 문서에도 이 문서를 가리키는 한 줄을 남긴다.

- **"한 화면 한 질문, 답한 것은 아래로 쌓인다"** — 답한 것은 위 고정 한 줄로 옮긴다. 아래 목록이
  긴 선택지에 밀려 보이지 않는다는 지적을 그대로 받았다. 한 화면 한 질문은 유지한다
- **"2. 진행바를 없앤다"** — `/eligibility` 에만 진행 표시("2/3 가구·소득")를 둔다. 1층은 질문 5개라
  요약 줄이 진행 표시 역할을 하지만, 2층은 한 화면에 여러 질문이 있어 어디쯤인지 따로 말해야 한다
- **"5. 테두리를 걷어낸다"** — 선택 안 된 선택지 카드에만 옅은 테두리(`ring-1 ring-ink-200` 수준)를
  넣는다. 선택된 카드와의 대비가 약하다는 지적("선택된 부분 하이라이트") 때문이다. 카드 이외의 무테 원칙은 유지한다

## 이동 규칙

### 단계 주소

| 화면 | 주소 | 비고 |
|---|---|---|
| `/find` | `?q=birth` `region` `status` `income` `housing` | 시군구 목록은 `?q=region&p=<시도명>` |
| `/calculate` | `?s=1` `2` | |
| `/eligibility` | `?g=1` `2` `3` | |

- "다음"은 다음 단계 주소로 `router.push` 한다 — 기록이 하나 쌓인다
- 현재 단계는 주소에서 읽는다. 주소에 단계가 없으면 지금처럼 "첫 미답 단계(다 답했으면 마지막)"로
  `router.replace` 한다 — 기록을 늘리지 않는다
- 아직 답하지 않은 앞 단계를 건너뛴 주소로 바로 들어오면 첫 미답 단계로 `replace` 한다
  (예: 생년월일 없이 `?q=income`)
- 정적 export 에서 `useSearchParams` 는 `<Suspense>` 경계가 필요하다. 페이지 본문을 경계 안에 둔다

### 왼쪽 위 화살표 = 뒤로가기

`TopBar` 의 `onBack` 을 없애고, `backHref` 의 뜻을 "뒤로 가되, 앞 화면이 앱 밖이면 여기로"로 바꾼다.
prop 이름은 그대로 둔다 — `app/result/ResultState.tsx`(손대지 않는 파일)도 `backHref` 를 쓰므로,
이름을 바꾸면 그 파일을 고쳐야 한다. 의미만 바뀌어 그 화면도 함께 고쳐진다.

- 앞 화면이 이 앱 안이면 `history.back()`
- 이 탭에서 사이트에 처음 들어온 화면이면 `router.push(backHref)`
- "처음 들어온 화면" 판정: 탭에서 앱이 처음 로드될 때 그 주소를 `sessionStorage` 에 적는다
  (`perky.entry`). 현재 주소가 그것과 같으면 처음 화면으로 본다. 새로고침해도 sessionStorage 와
  브라우저 기록이 함께 남아 판정이 유지된다. sessionStorage 가 막히면 항상 `backHref` 로 간다
  (앱 밖으로 튕기는 것보다 안전하다)
- 문구는 "이전 단계로" 하나
- 화면별 `backHref`: `/find` → `/`, `/find/result` → `/find`, `/find/policies` → `/find/result`,
  정책 상세 → `/find/policies`, 신청 준비 → 정책 상세, `/calculate` → `/find/policies`,
  `/eligibility` → `/calculate`, `/result` → `/eligibility`, 요건 검토 → `/result`
  (지금 각 화면의 `backHref` 목적지와 같다)

### 하단 버튼

- 하단은 앞으로 가는 행동만 둔다
- 화살표와 같은 곳으로 가는 중복 버튼은 없앤다: `RequirementReview` 의 "결과로 돌아가기",
  정책 상세의 "다른 혜택 보기"(대상 아님·마감일 때의 하단 버튼 — 대신 버튼을 두지 않는다)
- 목적지가 다른 버튼은 남긴다: `/result` 의 "답변 수정하기"(→ `/eligibility?g=1`), 목록의 "조건 수정"
- 온보딩은 그대로 `router.replace` 로 `/find` 에 들어간다 — 질문 첫 단계에서 뒤로가기를 눌러도
  온보딩으로 되돌아가지 않는다

## 화면

### 상단 답 요약 줄 — 공통 컴포넌트 `AnswerSummaryBar`

```ts
interface SummaryItem { key: string; label: string; value: string; href: string }
<AnswerSummaryBar items={SummaryItem[]} lead?: React.ReactNode />
```

- `TopBar` 바로 아래에 `sticky` 로 붙는다(상단바와 함께 고정)
- 항목은 `value` 만 보이고 `·` 로 잇는다. 각 항목은 링크(`href` 로 `router.push`)라 누르면 그 단계로
  가고, 그 이동도 기록에 남는다. `aria-label` 은 "`label` 고치기: `value`"
- 한 줄을 넘으면 가로 스크롤(`overflow-x-auto`, 스크롤바 숨김). 줄바꿈하지 않는다
- 항목이 없으면 그리지 않는다
- `lead` 는 왼쪽 앞에 붙는 고정 영역 — `/eligibility` 의 진행 표시 자리

### `/find`

- 요약 줄에는 현재 질문보다 앞서 답한 것만
- `AnsweredStack` 을 없앤다(컴포넌트도 다른 사용처가 없으면 삭제)
- 사는 곳 값은 지금처럼 시군구 이름(`chipLabel`). 이름이 여러 시도에 겹치는 시군구(중구·동구·서구·
  남구·북구·강서구 등 — `REGION_HIERARCHY` 에서 계산)는 "부산 중구"처럼 시도 약칭을 붙인다
- 선택해도 자동으로 넘어가지 않는다. 지금처럼 "다음"

### `/calculate`

- 2단계(`?s=2`) 요약 줄에 1단계 답: 지역 · 계약 형태 · 보증금 · 월세(또는 연세)

### `/eligibility`

- **진행 표시**: 요약 줄 `lead` 에 "2/3 가구·소득". 이전 묶음은 항목으로 "기본 자격"(→ `?g=1`)
- **답 접기**: 답한 질문은 한 줄로 접는다 — "질문 요약 · 답 ✎". 누르면 펼친다.
  질문 요약은 `lib/steps.ts` 질문 정의의 짧은 라벨을 쓴다(없으면 정의에 추가)
- **자동 스크롤**: 질문에 답하면 다음 미답 질문을 화면 안으로 스크롤한다(`scrollIntoView({ block:
  "center" })`). `prefers-reduced-motion` 이면 `behavior: "auto"`
- **미답일 때 "다음"**: 첫 미답 질문으로 스크롤하고 그 질문 제목에 포커스. 하단 한 줄 오류는 남긴다
- 판정 로직(`lib/steps.ts` 의 묶음·필터)은 바꾸지 않는다

### 선택 강조

- 선택된 `ChoiceCard`: 지금 그대로(`bg-brand-50 ring-2 ring-brand-600` + 체크)
- 선택 안 된 카드: 옅은 테두리 추가

### 덤

- 온보딩 문구 "네 가지" → "다섯 가지"(`app/onboarding/page.tsx:56`)

## 테스트

- **단위**
  - `useStepParam`: 주소 ↔ 단계 변환, 미답 단계 주소로 들어오면 첫 미답으로 replace, 주소 없으면 replace
  - `useBack`: 첫 진입 화면이면 `router.push(backHref)`, 아니면 `history.back()`, sessionStorage 가
    막히면 `backHref`
- **화면**
  - `/find`: "다음" → 주소가 다음 `q` 로 바뀐다. 요약 줄 항목 → 그 단계 주소. 겹치는 시군구 이름에 시도 약칭
  - `/eligibility`: 답한 질문이 접힌다. 미답으로 "다음" → 첫 미답 질문 제목에 포커스
  - `TopBar`: 문구 "이전 단계로", 두 분기
- **기존 테스트** — 단계 이동을 버튼 클릭으로만 검사하던 테스트는 주소까지 확인하도록 갱신.
  `next/navigation` 모크에 `useSearchParams` 를 더한다
- **통과 기준** — 휴대폰 뒤로가기와 왼쪽 위 화살표가 어느 질문 화면에서든 바로 전 단계로 간다.
  결과에서 거꾸로 올라가다 맨 처음 화면에서만 앱 밖으로 나간다. 위 재현표의 A·B·C 가 "기대" 와 같다

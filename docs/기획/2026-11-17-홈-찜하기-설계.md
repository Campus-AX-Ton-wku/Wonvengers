## 정한 것 (11/17)

| 항목 | 결정 |
|---|---|
| 누가 | **로그인한 사람만.** 로그인하지 않았으면 [찜하기]가 로그인 창(`app/find/policies/LoginSheet.tsx`와 같은 시트)을 띄운다 |
| 홈 내용 | **A 찜한 정책과 준비 진행률 · B 내 지원 요약 · D 내 조건 한 줄** (알림 칸 · 바로가기 묶음은 넣지 않는다) |
| 서류 체크리스트 | **섞기** — 정책에 서류 목록이 있으면 서류 하나하나, 없으면 지금의 확인 3개(자격 · 기간 · 서류) |
| 서류 데이터 | Supabase 정책 표 `documents` 칸. **영상에 나올 정책 2~3건은 팀이 원문 보고 먼저 입력**(추정 금지 F0-5) |
| 저장 | 지금의 답 저장(기기 → 계정, `lib/sync.ts` · DynamoDB `perky-user-data`)에 칸 두 개를 더한다 — 새 서버 · 새 표 없음 |

## 1. 찜하기

- 위치: 정책 목록 카드(`app/find/PolicyCard.tsx`) 오른쪽 위, 정책 상세(`PolicyDetail.tsx`) 제목 옆. ♡ 버튼(누름 영역 44px, 이름은 "{정책명} 찜하기"로 두고 상태는 aria-pressed 로 알린다 — 토글 버튼 표준, 11/17 결정).
- 로그인 안 했으면 로그인 창 → 로그인 뒤 그 화면으로 돌아온다(`signIn(현재 경로)`). 돌아와서 자동으로 찜하지는 않는다 — 한 번 더 누른다.
- 로그인했으면 누를 때마다 찜 ↔ 해제. 목록은 **최근에 찜한 것이 앞**. 최대 50건(넘으면 가장 오래된 것부터 빠진다).
- 목록 카드는 링크라서 ♡ 버튼이 카드 이동을 막는다(이벤트 전파 차단). 카드 안의 링크와 버튼은 따로 초점을 받는다.

## 2. 홈 화면 `/home`

정적 페이지. 로그인 기록이 없으면 `/onboarding` 으로 보낸다(replace).

| 순서 | 칸 | 내용 |
|---|---|---|
| 1 | 제목 + **D 내 조건** | "내 주거지원 현황" · "25세 · 익산시 · 재직" (`answerLine`, 목록 화면과 같은 어휘) · [조건 수정] → `/find` |
| 2 | **B 내 지원 요약** | "지금 받을 수 있는 지원금 N건"(1층 `splitByApplicationWindow` 의 신청 가능 수) → [목록 보기] `/find/policies`. 계산해 본 적이 있으면(`listing` · `profile` 저장됨) 결과 화면과 같은 계산(`buildCalculationSummary`)의 **명목 총 지출 → 최종 예상 주거비** → [결과 보기] `/result`, 없으면 [내 월세 계산하기] `/calculate` |
| 3 | **A 찜한 정책** | 카드: 정책 이름 · 기관 · 상태(D-day "D-12" / "상시" / "접수 마감" / "신청 예정") · 진행률 "서류 2/5 준비" 또는 "신청 준비 1/3"(+ 진행 막대). 누르면 `/find/policies/{id}/prepare`. 찜한 정책이 마감돼도 지우지 않는다(목록 화면과 다르다 — 직접 고른 것). 비면 "아직 찜한 지원금이 없어요" + [지원금 찾기] |

- D-day: 오늘(서울) ~ `applicationEnd`. 0일이면 "오늘 마감".
- 1층 답이 없으면(로그인했지만 질문 전) B 대신 "질문에 답하면 받을 수 있는 지원금을 찾아 드려요" + [시작하기] `/find`.
- 정책 데이터에서 사라진 찜(정책 삭제 · 공개 해제)은 홈에 그리지 않는다(저장은 그대로).

## 3. 신청 준비 체크리스트 (`/find/policies/[id]/prepare`)

- **서류 목록이 있는 정책**: "자격 조건 확인" · "모집 기간 확인" + 서류마다 한 줄(이름, 메모가 있으면 작게). 기존 "준비 서류 확인" 한 줄과 "서류 목록이 제공되지 않습니다" 안내는 그리지 않는다.
- **없는 정책**: 지금 그대로(확인 3개 + 안내).
- 진행률 = 체크한 수 / 전체(서류 있는 정책은 2 + 서류 수). 홈 카드의 "서류 2/5 준비"는 **서류만** 센다, 서류가 없으면 "확인 n/3".
- 맨 위에 찜 ♡ 버튼(이 화면에서 바로 찜할 수 있게).

## 4. 데이터

### Supabase — 정책 표 `documents`
- `documents jsonb` (비워 둘 수 있음): `[{ "name": "임대차계약서 사본", "note": "확정일자 포함" }, …]` — `name` 1~60자 필수, `note` 0~80자, 최대 15개, 이름 중복 불가(체크 키로 쓴다). check constraint 로 모양을 지킨다.
- 내용 칸이라 고치면 지금처럼 고친 이유 필요 · 버전 +1 · 미검수.
- `public.app_policies()` 가 `documents` 를 내보내고, `scripts/app-data/from-db.mjs` 가 `PolicyMeta.documents`(없으면 칸을 아예 적지 않는다)로 옮긴다. 검사: 모양이 틀리면 빌드 중단.
- 대출 · 저축 안내 상품(`loan-products.json`)에는 싣지 않는다(찜 대상은 지원금만).

### 앱 타입
- `PolicyMeta.documents?: { name: string; note?: string }[]`

### 계정 저장 형식 (`apps/web/lib/user-data.ts` — 웹 · API 공유)
- `saved: string[]` — 찜한 정책 id, 최근 것이 앞, 최대 50, 중복 불가, id 형식은 지금 체크리스트 키와 같은 규칙.
- `documentChecks: Record<string, string[]>` — 정책 id → 체크한 서류 이름들(각 1~60자, 정책당 최대 15, 정책 최대 50).
- **둘 다 없어도 받는다**(예전 앱 · 캐시된 홈 화면 앱이 보내는 저장). 읽을 때 없으면 `[]` · `{}`.
- 기기 저장 키: `perky.saved`, `perky.document-checks:<policyId>` — '처음부터 다시' · 로그아웃이 지우는 범위에 넣는다(지금 체크리스트와 같은 대우). `isEmptyContent` · `contentOf` · `sameContent` 에 포함. '처음부터 다시' 확인 시트가 "찜한 지원금과 서류 준비 체크도 함께 지워져요."라고 미리 알린다.
- `SCHEMA_VERSION` 은 올리지 않는다(칸 추가만, 없어도 받음).
- 처리방침 수집 항목에 "찜한 지원금 · 서류 준비 체크"를 더한다.

### 배포 순서
- 저장 형식이 바뀌어 API 재배포가 필요하다 → main 머지 때 'AWS 배포' 승인. **승인 전**에 새 화면에서 찜하면 서버가 모르는 칸이라 저장이 400 으로 실패한다 — 기기에는 남고 승인 뒤 다음 동기화에서 올라간다(`lib/sync.ts` 재시도). 승인을 바로 하면 된다.
- 단, 앱은 **비어 있는 찜 필드(`saved` `[]`, `documentChecks` 키 없음)를 업로드에서 뺀다**(`lib/sync.ts` `payloadFor`). 그래서 AWS 배포 승인 전에 400 "저장 안 됨"을 받는 사람은 **실제로 찜했거나 서류를 체크한 사람뿐**이다. 찜을 안 쓴 사람은 평소처럼 저장된다. 400 을 받은 사람의 기기에는 데이터가 남아 있고 배포 뒤 다음 동기화에서 올라간다.

## 5. 이동

- 시작 주소 `/`: 로그인 기록(`perky.auth`)이 있으면 **`/home`**, 없으면 지금처럼 `/onboarding` (`app/layout.tsx` 의 인라인 스크립트). 홈 화면에 추가한 아이폰 앱(start_url `/`)도 같다.
- 로그인한 사람의 상단바(`AccountSlot`)에 [홈] 버튼(집 아이콘, 이름 "홈").
- 로그인 콜백의 기본 돌아갈 곳은 그대로(로그인을 연 화면).

## 6. 테스트

- lib: 찜 목록 넣기 · 빼기 · 순서 · 50건 상한, 진행률 계산(서류 있음 / 없음), D-day, 홈 요약 계산.
- user-data: 새 칸 검사(모양 · 길이 · 중복 · 모르는 키), **새 칸 없는 예전 저장도 통과**.
- from-db: `documents` 옮기기 · 검사 실패.
- Supabase: 새 마이그레이션(칸 · check constraint · 함수) PGlite 검사.
- 화면: 홈 3칸의 상태별(찜 없음 · 계산 전 · 답 전), 찜 버튼(로그인 전 → 로그인 창, 후 → 토글), 체크리스트 섞기, `/` 이동.

## 하지 않는 것

- 로그인 없이 찜하기, 홈의 알림 칸 · 바로가기 묶음, 찜한 정책 마감 알림.
- 손필기 ⑦(청년 정책 뉴스 · 우리 지역 소개 · 학교 연결) — 나중에.
- 서류 목록 자동 수집(원문에서 추출) — 팀이 원문 보고 입력한다.

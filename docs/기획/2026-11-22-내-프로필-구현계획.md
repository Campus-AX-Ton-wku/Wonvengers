# 내 프로필 ① — 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 로그인한 사람이 프로필(그림 · 색 · 이름)을 꾸며 계정에 저장하고, 홈 인사와 새 내 정보 화면에서 본다.

**Architecture:** 서버 형식의 단독 출처 `lib/user-data.ts` 에 `profileCard` · `badges` 를 '없어도 받는 칸'으로 더하고(검사 · 다듬기 · 빈 값 판정),
`lib/storage.ts` 가 이 기기 키 두 개를 동기화 묶음에 넣는다. 화면 규칙(기본 이름 · 색 · 그림)은 순수 모듈 `lib/profile-card.ts`.
화면은 `ProfileAvatar`(공통) · 홈 인사 · 내 정보(프로필 카드 · 내 기록 · 설정 · 계정) · 꾸미기 창.

**Tech Stack:** Next.js 15(정적 export) · TypeScript · Tailwind 4(`dark:` = `[data-theme=dark]`) · Vitest · API(Lambda, 같은 검사 모듈)

**Spec:** `docs/기획/2026-11-22-내-프로필-설계.md`

## Global Constraints

- 서버가 모르는 키는 거절한다 → 새 칸은 `OPTIONAL_PAYLOAD_KEYS`, 웹은 비면 빼고 보낸다
- `lib/user-data.ts` 는 `./types` 타입 말고 import 하지 않는다(API 가 상대 경로로 가져감)
- 동의 버전은 올리지 않는다. 처리방침 · 동의 화면 수집 항목 한 줄만
- '처음부터 다시'는 프로필 · 배지를 남기고, 로그아웃은 지운다
- 이름 최대 10자(글자 단위), 기본 이름 규칙은 설계 2절
- 검증: `apps/web` 에서 tsc · vitest · build, `apps/api` 에서 vitest

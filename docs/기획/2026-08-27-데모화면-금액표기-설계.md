# 데모 화면 금액 표기·강조 위계 설계

작성일 2026-08-27. 대상은 IR덱에 실리는 세 화면 — `/find`, `/find/policies`, `/result`.

## 왜 이걸 하나

휠 데이트 피커를 고친 논리를 앱 전체에 대본 결과다. 그 개선은 두 줄로 요약된다.

1. 같은 동작을 두 번 배우게 하지 마라 (날짜 UI 를 하나로)
2. 손대지 않은 사람이 값을 제출하게 하지 마라 (빈 값 보존)

1번을 금액에 대보면 어긋난다. 같은 금액을 세 방식으로 쓴다.

| 화면 | 표기 | 출처 |
|---|---|---|
| `/find/policies` | `480만원`, `월 최대 21만 2,000원` | `formatKoreanMoney` |
| `/result` | `500,000원`, `4,900,000원` | `toLocaleString()` 직접 호출 |
| `/calculate` 입력칸 | 만원 단위 (`480` → 480만원) | `manwonToWon` |

`formatKoreanMoney` 가 이미 원하는 문자열을 준다. 검증했다.

```
500000  → "50만원"
4900000 → "490만원"
212000  → "21만 2,000원"
5400000 → "540만원"
```

즉 새 포매터를 만드는 일이 아니라, 있는 것을 안 쓰는 자리에 쓰는 일이다.

## 발견 — 캡처를 눈으로 본 결과

코드만 읽었을 때의 우선순위가 캡처를 보고 바뀌었다.

**`result.png` 의 가장 큰 숫자가 "내는 돈"이다.** `500,000원`(받는 돈)과
`4,900,000원`(내는 돈)이 같은 `text-3xl` 이다. 색은 다르지만 자릿수가 하나 더
많아 490만원이 시각적으로 압도한다. `result/page.tsx:77` 의 주석은 "받는 돈만
accent 로 띄운다"고 적혀 있는데, **자릿수가 색을 이긴다.** 지원금 서비스의 대표
캡처에서 심사위원 눈에 먼저 드는 숫자가 지출액이다.

**`policies.png` 의 가장 큰 금액이 마감된 정책에 붙어 있다.** 첫 카드가
`최대 480만원` + 초록 `가능성 있음` 인데 본문은 `2026-05-29에 접수가 끝났습니다`.

이 두 번째 건은 **태그 의미의 문제가 아니다.** `PolicyCard.tsx:43` 에 이유가
적혀 있다 — 1층 태그는 나이·지역·상태·소득만 보고, 접수 기간은 일부러 별도로
알려준다(PRD F3-6). 그 결정은 유지한다. 문제는 시각적 무게다.

## 범위

### 하는 것

**A. 금액 어휘 통일** — `result/page.tsx` 의 `toLocaleString()` 직접 호출 6곳을
`formatKoreanMoney` 로 교체한다 (헤드라인 2, 조합 목록 1, 카드 예상액 1, 명목
지출 1, 계약 당일 현금 1). `tabular-nums` 는 유지한다.

`명목 총 지출` 잔글씨만 원 단위로 남기는 안을 검토했으나, 한 카드 안에서 다시
두 표기가 되므로 통일한다.

**예외 하나 — 정책 카드의 산식은 원 단위로 남긴다.** 구현 중에 이 판단을 뒤집었다.
처음에는 "예외를 두지 않는다"고 적었으나, `benefitFormula` 의 성격이 다르다.

```
월 환산 월세 400,000원과 월 상한 212,000원 중 작은 값 × 12개월 = 2,544,000원
```

이 줄의 목적은 **사용자가 공고 원문과 대조하는 검산**이고, 공고가 원 단위로 적혀
있다. 만원으로 바꾸면 대조가 어려워진다. `lib/__tests__/benefit.test.ts` 가 이
문자열을 6곳에서 고정하고 있는 것도 이 줄이 계산의 산출물이라는 신호다.

그래서 통일 대상은 **사람이 읽는 금액**으로 한정한다 — 헤드라인 2, 조합 목록,
카드 단독 예상액, 명목 지출, 계약 당일 현금. `benefitFormula` 는 그대로 둔다.

**B. 강조 위계** — 받는 돈이 제일 크게.

```
지원금    text-3xl → text-5xl   accent-600 유지
주거비    text-3xl → text-xl    ink-900 유지
```

`text-5xl` 은 large text 기준(3:1)이라 `accent-600 on brand-50 = 4.76:1` 로
여유가 있다. 기존 주석의 대비 계산을 그대로 쓴다.

h1 이 바로 아래 카드와 같은 말을 반복하는 것도 함께 고친다. 현재 h1 두 줄
(`최대 지원 가능액과 / 최종 예상 주거비예요`)이 화면 상단을 먹고, 카드가 같은 두
라벨을 다시 단다. h1 을 한 줄로 줄여 캡처 첫 화면에 제목과 금액 카드가 함께
들어오게 한다.

h1 에 금액을 넣지 않는다. `app/page.tsx:30` 의 `MAX_BENEFIT` 주석이 정한 태도와
같다 — 확정되지 않은 금액을 가장 큰 약속으로 쓰지 않는다.

**C. 마감된 정책의 시각적 무게** — `window === "after"` 인 카드는 공고 상한
금액을 `accent-600` 이 아닌 중립색으로 내리고, `접수 마감` 을 태그와 같은 눈높이에
붙인다. 태그·금액·기간이 한 눈에 함께 읽히게 하는 것이 목적이다.

**D. 낡은 주석 제거** — `calculate/page.tsx:246` 이 존재하지 않는
`app/DatePicker.tsx` 를 가리키며 "생년월일은 아직 네이티브 select 다"라고 적고
있다. 이미 휠 피커로 통일됐다.

**E. 캡처 자동화** — `apps/web/scripts/capture-screens.mjs`. 손으로 찍으면
재현이 안 된다. `landing.png` 가 랜딩 개편 전 캡처로 남아 덱에서 빠진 게 그
결과다. 뷰포트 `390x844` × `dsf 2` = `780x1688` 로 기존 규격을 고정하고,
`addInitScript` 로 `localStorage` 를 주입한다.

`landing.png` 도 갱신하되 **덱 구성(`build-ir-deck.py` 의 `SHOT` 3장)은 그대로
둔다.** 덱에 몇 장을 넣을지는 발표 서술의 문제다.

### 하지 않는 것 (2단계로 미룸)

`/calculate`·`/eligibility` 의 개선은 미룬다. 두 화면은 덱에 실리지 않고, 시연은
녹화·캡처라 라이브 타이핑도 없다. 지금 손대면 캡처되지 않는 곳에 시간을 쓴다.

실사용자 배포로 넘어갈 때의 1순위 목록으로 남긴다.

1. **선택 위젯 3종 혼재** — 날짜만 통일됐다. 나이·지역·출처·가구원수는 네이티브
   `<select>`, 금액은 `type=number` (`find/page.tsx:96`, `calculate/page.tsx:190,278`)
2. **한 스텝에 문항 6개** — "쌓아두면 눌려 이탈한다"며 3그룹으로 나눴는데 1·3
   그룹이 각각 6문항이다 (`lib/steps.ts:23,45`). 분할 논리가 절반만 적용됐다
3. **필드별 에러 표시 없음** — 하단에 한 줄만 뜬다. 6문항 스텝에서 어느 칸이
   문제인지 찾아야 한다 (`eligibility:123`, `calculate:306`)
4. **`모름` 의 대가가 고르는 순간 안 보인다** — 결과에서야 "확인되지 않은 조건"
   으로 등장한다 (`result/page.tsx:95`)
5. **목록 정렬** — 신청 가능한 정책을 위로 올리면 C 를 더 근본적으로 해결한다.
   `lib/discovery.ts` 의 그룹 순서를 건드리므로 영향 범위가 넓어 이번에는 뺐다
6. **예시가 판정 문항을 채우지 않는다** — `exampleToListing` 은 `ListingInput`
   만 채운다. 라이브 시연을 하게 되면 16문항이 죽은 시간이 된다
7. **폰트를 웹폰트로 싣지 않는다** — `globals.css` 가 Pretendard 를 1순위로
   지정하지만 불러오지 않아, 기기마다 다른 글꼴로 보인다 (아래 '구현 중 알게 된 것')

## 테스트

`/result` 에는 UI 테스트 파일이 없다. 덱의 세 장 중 가장 중요한 화면인데
`app/__tests__/` 에 `result.test.tsx` 가 없고, QA체크리스트의 결과 항목이 대부분
**직접 클릭**으로 남아 있는 것과 일치한다.

`app/__tests__/result.test.tsx` 를 새로 만든다. 기존 관례를 따른다 —
`// @vitest-environment jsdom`, `next/navigation` 모킹, `lib/__tests__/fixtures.ts`
의 `makeListing`/`makeProfile` 재사용.

- 헤드라인 금액이 만원 단위로 나온다 (`50만원`, `490만원`)
- 원 단위 전체 자릿수(`500,000원`)가 화면에 없다
- 지원금 글씨가 주거비보다 크다 (클래스로 검증)
- 마감된 정책의 공고 상한이 `accent` 색이 아니다

캡처 스크립트는 테스트 대상이 아니다. 개발 도구이고, 실패하면 그 자리에서
드러난다(문구를 못 찾으면 exit 1).

## 알려진 미해결

**캡처 fixture 가 기존 `result.png` 의 조건과 다르다.** 기존 캡처는
`계약 당일 필요한 현금: 3,000,000원 (보증금)` 이라 계약 형태가 월세인데, 이사비
산식은 `실제 일시 지출 600,000원` 을 쓴다 — `example-listings.json` 의 어느
예시와도 맞지 않는, 손으로 입력한 조건이다.

스크립트 fixture 는 문서화된 데모 예시(`익산 원룸 · 연세` + 이사비 60만원)를
기준으로 짰다. 이대로 찍으면 계약 당일 현금이 780만원(보증금 300만 + 연세 선납
480만)으로 올라가 **덱의 숫자가 바뀐다.** 연세 캡핑 이야기를 보여주려면 이게
맞지만, 기존 덱 서술과 어긋날 수 있어 팀 확인이 필요하다.

## 구현 중 알게 된 것

**캡처를 눈으로 보고 되돌린 것이 있다.** `text-5xl` 로 올렸더니 390px 폭에서
`304만 4,000원` 이 두 줄로 넘치고 `원` 만 다음 줄에 떨어졌다. 만 단위 표기가 원
단위보다 길어질 수 있다는 것을 캡처를 보고서야 알았다. `text-4xl` + `break-keep`
으로 되돌렸다.

테스트는 이때 통과하고 있었다 — `text-5xl` 을 클래스명으로 고정했기 때문이다.
그래서 테스트를 **관계**로 고쳤다(`글씨크기(지원금) > 글씨크기(주거비)`). 크기
숫자를 조정해도 지켜야 할 것은 그 관계다.

**WSL 에서 캡처가 조용히 낡는다.** `/mnt/c` 에서는 inotify 가 동작하지 않아 Next
dev 가 파일 변경을 못 잡는다. 코드를 고친 뒤 캡처하면 낡은 화면이 찍히는데,
스크립트는 성공으로 끝난다. `WATCHPACK_POLLING=true` 로 띄우거나 재시작해야 한다.
스크립트 헤더에 적어뒀다.

**폰트가 앱의 약한 고리다.** `globals.css` 의 스택은
`Pretendard → Apple SD Gothic Neo → Malgun Gothic → sans-serif` 인데 **웹폰트로
불러오지 않는다.** 기기에 없으면 폴백된다 — 윈도우는 Malgun Gothic, 맥은 Apple SD
Gothic Neo, 안드로이드·리눅스는 제각각이다. 즉 지금 사용자가 보는 글꼴은 기기마다
다르고, 디자인이 의도한 Pretendard 를 보는 사람은 그것을 따로 설치한 사람뿐이다.

캡처 환경에는 Pretendard 를 설치해 해결했지만, **앱 자체는 그대로다.** 웹폰트로
싣는 것은 이 스펙의 범위 밖이라 2단계 목록에 넣는다 (7번).

**Playwright 시스템 라이브러리는 sudo 없이 해결했다.** `libnss3`·`libnspr4`·
`libasound2t64` 를 `apt-get download` 후 로컬에 풀고 `LD_LIBRARY_PATH` 로 붙였다.
`~/.local/pw-libs` 에 있다. 팀원 환경에서는 `sudo apt-get install` 이 더 간단하다.

## 남은 판단 — 캡처 fixture

기존 `result.png` 의 조건을 복원하지 못했다. 기존 캡처는
`계약 당일 필요한 현금: 3,000,000원 (보증금)` 이라 계약 형태가 월세인데, 이사비
산식은 `실제 일시 지출 600,000원` 을 쓴다 — `example-listings.json` 의 어느
예시와도 맞지 않는, 손으로 입력한 조건이다.

스크립트 fixture 는 문서화된 데모 예시(`익산 원룸 · 연세` + 이사비 60만원)를
기준으로 짰고, 값은 `lib/__tests__/fixtures.ts` 의 `makeProfile` 과 맞췄다 —
테스트가 보는 상태와 캡처에 찍히는 상태가 갈리면 통과한 테스트가 캡처를
보증하지 못한다.

그 결과 덱의 숫자가 바뀌었다.

| | 이전 캡처 | 지금 |
|---|---|---|
| 최대 지원 가능액 | 500,000원 | 304만 4,000원 |
| 최종 예상 주거비 | 4,900,000원 | 271만 6,000원 |
| 계약 당일 현금 | 3,000,000원 (보증금) | 780만원 (보증금 + 연세 선납액) |
| 합산된 정책 | 1건 | 2건 |

연세 캡핑 이야기를 보여주려면 이 fixture 가 맞지만, 발표 서술이 이전 숫자를 전제로
쓰여 있다면 팀이 fixture 를 정해야 한다. `scripts/capture-screens.mjs` 의
`FIXTURE` 한 곳만 고치면 된다.

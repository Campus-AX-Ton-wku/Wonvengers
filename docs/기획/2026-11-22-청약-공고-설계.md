## 1. 공고 모으기 — 빌드할 때

- **`apps/web/scripts/fetch-notices.mjs`** — `prebuild` 에서 `fetch-app-data.mjs` 다음에 돈다
  1. 마이홈 임대 · 분양(`brtcCode=52`, `signguCode=140`, 쪽 넘김)
  2. 청약홈 아파트 · 무순위(공급지역 '전북', 쪽 넘김) → `HSSPLY_ADRES` 에 '익산'이 있는 것만
  3. 한 모양으로 맞춘다(아래 `HousingNotice`) → 공고 ID 로 합친다 → **접수가 끝난 공고는 뺀다**
  4. `data/notices.json`(앱이 가져다 쓴다) · `public/notices.json`(알림 서버가 읽는다)에 쓴다
- **실패해도 빌드는 멈추지 않는다.** 공고는 보조 정보라 정책(실패하면 빌드 멈춤)과 다르다 — 키가 없거나 API 가 실패하면 커밋된 `data/notices.json` 스냅숏을 그대로 쓰고 경고만 남긴다. 스냅숏의 '기준 시각'은 화면에 그대로 보인다(§2)
- **하루 한 번 재빌드** — Supabase `pg_cron` 에 매일 서울 06:00(UTC 21:00) 작업 `app-rebuild-daily` 를 더한다. 하는 일은 **재빌드 지문(`private.app_rebuild_state.last_hash`)을 지우는 것 하나** — 5분마다 도는 `app-rebuild` 가 다음 회차에 지문이 다르다고 보고 Vercel 을 한 번 부른다. 주소(Vault) · 실패 재시도 · 대기 시간은 지금 `private.request_app_rebuild()` 를 그대로 쓴다(구현 계획 쓰며 정함)
- **설정** — 새 환경변수 없음. 키는 **`BOJOGEUM_KEY`** 그대로(같은 공공데이터포털 일반 인증키, 서류 떼는 곳 지도 때문에 Vercel Production · Preview 에 이미 있다). 키는 빌드 때만 쓰고 화면 · 파일 · 로그에 나가지 않는다

## 2. 화면

### `/housing` — 익산 청약 공고 (로그인 없이)
- 상단 ←(`/home`), 제목 '익산 청약 공고', 한 줄 "공공임대 · 공공분양 · 아파트 분양 · {기준 날짜} 기준"
- 종류 칩: 전체 · 공공임대 · 공공분양 · 아파트 분양 · 무순위 · 잔여 — **0건인 칩은 숨긴다**
- 두 묶음: **'접수 중'**(마감 가까운 순) · **'접수 예정'**(시작 가까운 순). 끝난 공고는 없다
- 카드: 종류 배지(`typeLabel`) · 공고명 · 공급기관 · 접수 기간 + D-day(`DeadlineBadge` 공용) · **[공고문 보기 ↗]**(새 창 `url`). '신청 가능' 같은 판정 표시는 없다. 상세 화면은 만들지 않는다
- 아래 안내: "자격과 소득 기준은 공고마다 달라요. 꼭 공고문에서 확인해 주세요." · 출처 "마이홈포털 · 청약홈 (매일 아침 갱신)"
- 0건: "지금 익산에 접수 중인 청약 공고가 없어요" + [청약 쉽게 알아보기](가이드)

### 홈 칸 '익산 청약 공고' (로그인한 사람)
- 자리: **다가오는 일정 아래, 주거 가이드 위** (마감이 있는 정보라 가이드보다 위). 지금 순서: 오늘 할 일 → 요약 → 다가오는 일정 → **청약 공고** → 주거 가이드 → 대출 · 보증
- 모양: 대출 · 보증 줄과 같다 — 제목 + '전체 보기 ›'(`/housing`), 가로 카드 최대 3장(접수 중 → 예정)
- 0건이면 칸째 숨김
- 하단 탭은 늘리지 않는다(5칸)

## 3. 알림

### 알림함 — "익산에 새 청약 공고가 올라왔어요"
- `lib/inbox.ts` 에 종류 `notice` — 모집공고일 **14일 이내**이고 끝나지 않은 공고. 키 `notice:{id}`, 누르면 `/housing`
- 읽음 · 빨간 점은 지금 방식(`perky.inbox.seen`) 그대로
- 사는 곳을 답하지 않았으면 띄우지 않는다('새 지원금'과 같은 규칙, 11/08 결정)

### 휴대폰 푸시 — 새 공고 묶음
- 알림 서버(매시)가 `/policies.json` 과 함께 **`/notices.json`** 을 읽는다. 처음 보는 공고 ID 가 있으면 보낸다
- 상태: `perky-push` 표에 `__state__`/`announced-notices` 항목(새 정책의 `announced` 와 따로). **처음엔 지금 공고를 전부 '이미 알림'으로 표시만** 하고 보내지 않는다(새 정책 알림을 처음 켤 때와 같다)
- 받는 사람: 알림을 켜고 사는 곳이 익산인 사람
- 한 통으로 묶는다: 제목 "익산에 새 청약 공고가 올라왔어요", 본문 "{첫 공고명} 외 N건"(1건이면 공고명만), 누르면 `/housing`, tag `notice`
- 시간: 새 정책과 같은 서울 9~21시. 공고는 아침 6시에 갱신되니 대개 9시 회차

### 알림 설정
- 종류별 켜기 · 끄기는 만들지 않는다. 설명 문구에 '새 청약 공고'를 더해 무엇이 오는지 보이게 한다

### 처리방침
- 휴대폰 알림의 쓰임에 '새 청약 공고 알림' 한 줄

## 4. 청약 가이드 '청약 쉽게'

`lib/guides.ts` 의 지금 형식(장마다 용어 + 비유 + 공식 출처, 한 장에 한 섹션 `/guides/[id]/[step]`)

| 장 | 내용 |
|---|---|
| 1. 청약이 뭐예요 | 새 집 · 공공주택에 '줄 서기 신청'. 번호표 · 추첨 비유 |
| 2. 청약통장 | 통장이 있어야 줄을 선다 → 앱의 **청년 주택드림 청약통장**(`/loans/youth-dream-savings-account`) |
| 3. 임대 vs 분양 | 빌려 사는 집(행복주택 · 국민 · 영구 · 매입임대) vs 사는 집(공공분양 · 민간분양) |
| 4. 청년이 노릴 수 있는 자리 | 행복주택 청년 계층 · 공공분양 청년 특별공급 등 — **숫자 기준은 공식 출처로 확인한 것만** 확인 날짜와 함께 |
| 5. 어디서 신청해요 | 분양 → 청약홈, LH 임대 · 분양 → LH청약플러스, 찾기 → 마이홈포털 |
| 6. 공고문 읽는 법 | 모집공고일 기준 자격 · 소득 · 자산 표 · 접수 기간 · 발표일 · 서류 |

- 끝에 [익산 청약 공고 보기 →](`/housing`)
- 공식 페이지(청약홈 · 마이홈포털 · LH · 국토교통부)에서만 가져온다. 확인 못 한 숫자는 넣지 않는다
- **ggue 가 PR 에서 내용을 확인한 뒤 공개**

### 7.1 화면 — `/housing/notice?id=<공고 ID>`

- 정적 export 라 `[id]` 경로는 공고가 0건인 날 빌드가 깨진다 → **물음표 주소** 한 장. 브라우저에서 `window.location.search` 로 읽는다(Suspense 없이 — `auth/callback` 과 같은 방식)
- 위에서부터
  1. 배지(주택 종류 · 마감 D-n) · 제목 · 공급기관 · 접수 기간
  2. **일정** — 모집 공고 · 접수(청약홈은 특별공급 · 1순위 · 2순위 따로) · 당첨자 발표 · 계약 · 입주 예정
  3. **단지**(마이홈) — 단지마다 이름 · 주소 · 공급 N호 · 난방 · 금액(임대: 보증금 · 월 임대료, 분양: 계약금 · 중도금 · 잔금). 0원 · 빈 값은 뺀다. 밑에 "**가장 낮은 조건 기준이에요.** 내 조건의 금액은 공고문에서 확인해 주세요."
  4. **주택형별 공급금액**(청약홈 아파트) — 주택형(전용 ㎡) · 공급 세대(일반 · 특별) · 공급금액(최고가 기준). 밑에 "청약홈 기준 · 같은 주택형도 층 · 동에 따라 달라요"
  5. 공급 규모 · 시행 · 시공
  6. 문의 — 지금 `ContactInfo` 그대로(마이홈 `refrnc` 에서 전화번호를 뽑는다, 청약홈은 견본주택 전화 · 홈페이지)
  7. "자격과 소득 기준은 공고마다 달라요…" · 출처 · N월 N일 기준
  - 아래 고정 버튼 **[공고문 보기 ↗]** — 원문(새 창)
- 없는 ID · 끝난 공고 → "끝났거나 내려간 공고예요" + [익산 청약 공고 보기](`/housing`)
- 들어오는 길: `/housing` 카드 · 홈 칸 카드 · 알림함 줄이 이 페이지로 간다(지금은 카드 = 원문 새 창, 알림함 = `/housing`)

### 7.2 데이터 — 공고에 `detail` 하나 더

- 새 파일 `lib/notice-detail.ts` — `NoticeDetail` 과 `DetailedNotice = HousingNotice & { detail?: NoticeDetail }`. 알림 서버가 가져다 쓰는 `lib/notices.ts` 는 그대로(다른 칸은 알림 서버가 읽지 않는다)
- `detail` 은 화면이 바로 그리는 모양 — 일정 · 단지 · 주택형 · 개요 · 문의. 빌드 스크립트(`scripts/notices/build.mjs`)가 만든다
  - 마이홈: 같은 공고 ID 의 줄을 **합치며 단지를 모은다**(지금은 첫 줄만 남기고 버린다)
  - 청약홈 아파트: 합친 뒤 남은(끝나지 않은) 익산 공고만 주택형 API 를 부른다 — 한 번에 몇 건이라 호출이 적다. **주택형 호출이 실패하면 표만 빠진다**(목록 · 나머지 상세는 그대로, 빌드 안 멈춤)
- `detail` 이 없는 공고(예: 예전 스냅숏)도 화면이 깨지지 않는다 — 기본 칸만 보인다

### 7.3 시험

- 빌드 스크립트: 마이홈 단지 합치기(같은 ID 두 줄 → 단지 2개) · 0원 · 빈 값 빼기 · 정정공고는 그대로 대신함, 청약홈 일정(`"null"` 문자열 · 빠진 칸) · 입주 `YYYYMM` · 전화번호 모양, 주택형 변환(`059.8500A` → 59.85㎡ A, 만원 → 원) · 주택형 호출 실패 → 표만 없음
- 화면: 마이홈 공고(단지 2개 · 금액 · 안내 문구) · 청약홈 공고(주택형 표) · `detail` 없는 공고 · 없는 ID · 끝난 공고 · 카드 / 홈 / 알림함 링크가 상세로
- 실제 확인: 배포 뒤 `/housing` → 카드 → 상세, 공고문 버튼

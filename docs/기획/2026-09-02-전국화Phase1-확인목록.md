# 전국화 — 사용자 확인 목록 (누적, Phase 1부터)

> Phase 1(전북 6개 시 파일럿)부터 Claude 가 원문에서 확인하지 못한 항목을
> 여기 계속 쌓는다. F0-5 원칙대로 확인 안 된 값은 `policies.json`·
> `loan-products.json`에 추정해서 채우지 않았다 — 이 목록이 그 빈 자리다.
> Phase 마무리 시점마다 이 파일을 기준으로 정리해 전달한다.

### 2. 김제시 청년농촌보금자리 조성사업
`policies.json`·`loan-products.json` 어디에도 넣지 않고 후보 문서에 보류로 기록함
(`docs/기획/온통청년-주거후보.md`의 "검토 완료" 절 참고).

- **김제시가 직접 낸 공고 원문을 찾지 못했다.** "개인 신청형이 아니라 시설 조성 사업이다"는 판단은 농림축산식품부의 전국 사업 개요·타 지자체(하동군) 사례·온통청년 API의 빈 신청 필드라는 정황 증거로 내린 것이지, 김제시 원문으로 확정한 게 아니다

- 온통청년 API의 `aplyYmd`(2026-12-01~2027-03-31)가 무엇을 뜻하는지 — 완공 예정일 범위인지, 향후 입주자 모집 예정 기간인지

**확인 방법**: 김제시청 인구정책과 또는 건설과에 직접 문의 필요 (전화번호를 원문에서 찾지 못함 — 김제시청 대표전화 063-540-3114를 통해 담당부서 연결 필요)

## 팀 판단이 필요한 항목 (사실 확인이 아니라 제품/스키마 결정)

### 4. 전주시 청춘★별채 — 스키마 갭 — ✅ 해결됨 (2026-09-02, Phase 2 라운드 2)
옵션 B(별도 파일/타입으로 분리, `loan-products.json`과 형제 패턴)로 결정. 새 타입
`HousingSupplyMeta`(`lib/types.ts`)와 새 파일 `data/housing-supply.json`을 만들어
1층·2층 판정 파이프라인·`benefit.ts` 계산 로직을 건드리지 않고 `/result`에
안내 전용 섹션으로만 노출한다. 지역 필터(`housingSupplyForRegion`)도 대출상품과
같은 규칙을 재사용해 처음부터 적용했다. 더 이상 판단이 필요 없다 — 근거는
아래 7번 참고.

### 5. `loan-products.json`의 지역 노출 범위 — ✅ 해결됨 (2026-09-02)
`/result` 화면의 "이용 가능한 대출·보증 상품" 섹션이 `loan-products.json`의
모든 항목을 지역 필터링 없이 전체 노출하던 문제. `lib/region.ts`에
`loanProductsForRegion`을 추가해(`policiesForRegion`과 같은 `policyAppliesToRegion`
규칙을 공유) 고쳤다. 회귀 테스트(`region.test.ts`, `result.test.tsx`) 추가,
브라우저로 익산/그 외 지역 두 경우 다 실측 확인함. 더 이상 확인·판단이 필요 없다.

### 6. `policies.json`과 `loan-products.json`에 같은 정책이 중복으로 존재
"전세보증금반환보증 보증료 지원"이 두 파일에 **같은 이름으로 각각** 들어있다.
`policies.json`에는 확정 검증된 `lump_sum`형 정책으로(`verifiedAt: 2026-08-31`),
`loan-products.json`에는 `verifiedAt: null`인 미검증 초안(`guarantee_fee_subsidy`)으로
남아 있다 — 위 항목 5번을 고치는 과정에서 `/result` 화면에 이 정책명이 **두 번**
렌더되는 것을 실측으로 확인했다(정책 카드 섹션 한 번 + 대출상품 섹션 한 번).

git 이력으로 확인했다: `loan-products.json`의 항목이 2026-08-20(`9019a2e`)에 먼저
미검증 초안으로 들어갔고, `policies.json`의 정식 검증 항목은 2026-09-01(`36b749a`)에
나중에 추가됐다 — `loan-products.json`의 옛 항목을 지웠어야 하는데 지우지 않은 것이다.
이건 사실 확인이 아니라 **정리 판단이 필요한 항목**이다: `loan-products.json`의 이
항목을 지울지, 지운다면 언제(이번 Phase 1 범위인지 별도 정리 작업인지) 팀이 정해야 한다.

### 7. "저가 주거 공급형" 정책 스키마 갭 — ✅ 해결됨 (2026-09-02, Phase 2 라운드 2)
4번과 같은 결정(옵션 B)으로 **대학생 연합생활관(은행권,고양)**도 `data/housing-supply.json`에
함께 등록했다(`kosaf-goyang-dormitory`). 한국장학재단 공지사항 원문으로 확인 —
월 15만원(6개월 생활관비 90만원 환산)·보증금 15만원이 온통청년 API 값과 정확히
일치했다. 이 정책은 신청기간이 학기마다 반복되는 구조라 청춘★별채처럼 단일
`applicationStart`/`applicationEnd`로 못 담아, `applicationPeriodNote`(반복 주기
설명) 필드를 따로 둬서 표현했다 — 다음 정확한 모집 일정은 위 3-1번에 확인 필요로
남아 있다.

### 8. "청년주택드림청약통장" — 대출도 보증료 지원도 아닌 청약저축 상품 — ✅ 해결됨 (2026-09-02, Phase 2 라운드 2)
`loan-products.json`의 `productType`에 `savings_account`를 추가해 등록했다
(`youth-dream-savings-account`). 주택도시기금 공식 페이지(상품기준일 2026-06-30)
원문으로 이자율 구간(2년~10년 연 4.5%, 그 외 2.3~3.1%)까지 확인했다. ⚠️ 다만
API의 "월 납입한도 100만원"·"소득공제 연 300만원 한도 40%"는 이 공식 페이지에서
직접 재확인하지 못해 `notes`에 확인 필요로 남겨뒀다(요약문에는 안 옮김) — 필요하면
이 부분만 추가로 원문 대조하면 된다.

### 9. "전세사기 피해 예방 및 지원 강화" — 단일 정책으로 특정이 안 됨

Phase 2 라운드 1에서 나온 셋째 항목. 온통청년 등록 설명이 "저리·대환대출 등 금융지원,
우선매수권 양도를 통한 매입임대 등 주거지원 등을 제공"이라고 돼 있는데, 이건 전세사기
피해자 지원 특별법 아래 묶인 여러 세부 시책을 통틀어 부르는 이름이다. 이 이름 하나로
등록하면 사용자가 무엇을 신청하는 건지 알 수 없다 — 세부 시책(예: 저리 대환대출)을
따로 찾아 개별 정책으로 발굴할지, 이 항목 자체는 포기할지 팀 판단이 필요하다.

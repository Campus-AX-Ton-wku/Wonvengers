## 왜

## 결정 사항

| 질문 | 결정 |

| 신뢰의 기준 | 정확성 + 빠짐없음. 12건 전부 원문 대조하고, 빠진 익산 항목이 없는지 다시 훑는다 |

때마다 두 파일을 고쳐야 한다. 익산 12건 규모에서는 이득이 작아 택하지 않았다.

## 데이터

### `contact` — 세 타입(`PolicyMeta`, `LoanProductMeta`, `HousingSupplyMeta`) 공통

```ts
contact: {
  department: string;           // "익산시 청년정책과", "주택도시보증공사 고객센터"
  phone: string | null;         // "063-859-5745" 형식
  url: string | null;           // 문의 게시판·담당 안내 페이지
  phoneCheckedAt: string | null; // 팀이 이 번호로 전화해 확인한 날 (YYYY-MM-DD)
} | null;                       // null = 아직 확인 못 함
```

- F0-5: 확인 못 한 값은 채우지 않는다. 공고에 부서만 있고 번호가 없으면 `phone: null`
- 익산 12건은 모두 채운다. 다른 지역 항목은 `null` 로 두고, 화면은 null 이면 그리지 않는다

### `nextRound` — 세 타입 공통

```ts
nextRound: {
  text: string;          // "2027년 4월 공고 예정"
  confirmedAt: string;   // YYYY-MM-DD
  via: "공고" | "전화";
} | null;
```

- 마감된 항목에만 쓴다. 공고문이나 팀 전화로 확인한 경우에만 채운다

### `data/consult-centers.json` — 신규

```ts
interface ConsultCenterMeta {
  id: string;
  name: string;          // "익산청년시청"
  regionScope: string;   // 정책과 같은 규칙. "전국" 또는 시도/시군구 접두사
  phone: string | null;
  url: string | null;
  hours: string | null;  // "평일 09:00~18:00"
  topics: string[];      // ["청년 주거", "월세 지원 신청"]
  verifiedAt: string | null;
  notes: string;         // 내부 메모. 화면에 그리지 않는다
}
```

- 지역 매칭은 기존 `policyAppliesToRegion` 과 같은 접두사 규칙을 쓴다
- 후보: 익산청년시청, 전북청년허브센터, 마이홈 상담센터(전국). 조사하면서 확정한다

### 정리

- 중복된 `jeonse-return-guarantee-fee-subsidy` 는 성격(현금 지원인지 보증료 지원인지)을
  원문으로 확인해 한쪽만 남긴다
- 12건의 `applyUrl` 을 홈페이지 루트가 아니라 실제 신청·공고 페이지로 바꾼다.
  상시 페이지가 없으면 공고 목록 페이지로 둔다

### 빠짐없음

- 익산시청 고시공고, 전북특별자치도, 온통청년, 복지로를 익산 기준으로 다시 훑는다.
  `scripts/discovery-region.mjs` 를 쓴다
- 새 항목은 CLAUDE.md "정책 1건 추가할 때" 절차대로 등록하고 `docs/기획/온통청년-주거후보.md`
  에 판정을 남긴다

## 화면

### 정책 상세 (`PolicyDetail.tsx`)

- 하드코딩된 "신청 방법: 공식 사이트" 자리에 **문의** 블록을 둔다:
  담당 부서, 누르면 바로 전화가 걸리는 번호(`tel:` 링크), 문의 페이지 링크.
  `contact` 가 null 이면 기존 문구를 유지한다
- `SourceNotice` 에 `phoneCheckedAt` 이 있으면 "담당 부서에 전화로 확인했습니다 (MM.DD)"
  한 줄을 추가한다
- 마감된 정책에 `nextRound` 가 있으면 마감 안내 옆에 "2027년 4월 공고 예정 · 전화 확인"을 붙인다

### 신청 준비 (`ApplicationPreparation.tsx`) 와 이동 모달

- 출처·최종 확인일 아래에 문의처 한 줄

### 결과 화면 대출·주택 카드 (`result/page.tsx`)

- 출처 링크 줄에 "문의 063-…" 추가
- 정책 카드(`BenefitResultCard.tsx`)는 다른 팀원 담당이라 건드리지 않는다.
  정책의 연락처는 상세 화면에서 보여준다

### 지역 상담 창구

- `/find` 에서 시군구를 고른 직후, "다음" 버튼 위에 한 줄 요약:
  "익산시 · 지원 정책 6건 · 상담 창구 3곳"
- `/find/policies` 목록 맨 위에 접힌 카드 **"익산에서 상담받을 수 있는 곳"**.
  창구마다 이름, 전화(`tel:`), 운영 시간, 상담 주제. 창구가 0곳이면 카드를 그리지 않는다

### 커버리지 정직하게 표시

- 익산 외 지역 사용자에게는 `/find/policies` 목록 위에
  "이 지역은 아직 정보를 모으는 중이라 빠진 지원이 있을 수 있어요" 를 보여준다
- 랜딩의 "주거 지원금 35개" 는 사실 문구(예: "익산 기준 원문·담당자 확인 완료")로 바꾸는
  것을 검토한다. 문구는 구현할 때 사용자에게 보여주고 정한다

# 발표 자료

| 파일 | 내용 |
|---|---|
| `Perky_IR덱.pptx` | IR덱 6장 (16:9 · 13.333 × 7.5in) |
| `build-ir-deck.py` | 위 덱을 만드는 스크립트 |

## 덱 다시 굽기

```bash
pip install python-pptx
python3 docs/발표/build-ir-deck.py
```

화면 캡처는 `docs/이미지/{find,policies,result}.png` 를 읽는다.
**새로 찍어 같은 파일명으로 덮어쓰고 다시 돌리면 반영된다.**

> [!NOTE]
> `docs/이미지/landing.png` 는 랜딩을 개편하기 전(건물 그래픽 · 가운데 60px 워드마크)
> 캡처라 덱에 넣지 않았다. 새로 찍으면 1장이나 3장에 넣을 수 있다.

## 구성

| 장 | 심사 축 | 담은 것 |
|---|---|---|
| 1 | 문제정의 | 네 기관이 따로 공고를 낸다 → 대상자가 자기가 받을 수 있는지 모른다 |
| 2 | — | 두 층 구조 (발견 / 계산). "1층만 완성되어도 제품으로 성립한다" |
| 3 | 프로토타입 | 실제 화면 3장 + 데모 동선 |
| 4 | **AI 활용** | "판정을 AI에 맡기지 않았다" — 왜 안 썼나 / 대신 무엇을 했나 |
| 5 | 프로토타입 | 지표 + 기준 중위소득이 2027년 값이었던 발견 사례 |
| 6 | — | 남은 리스크(미검수 1건)를 먼저 말하고, 다음 단계와 팀 |

색·폰트는 `docs/디자인/design-tokens.md` 팔레트를 그대로 쓴다 (`brand-600`,
`accent-600` 은 금액·강조 전용 규칙 유지). 덱과 제품이 같은 톤으로 읽히게 하려는 것이다.

## 수치를 고칠 때

정책 상한·테스트 수·PR 수는 스크립트에 손으로 적혀 있다. 자동으로 읽지 않는 이유는
발표 자료라 사람이 한 번 확인하는 편이 낫다고 봤기 때문이다. 레포가 바뀌면
`build-ir-deck.py` 의 해당 문자열을 고친다.

- 정책 상한 → `apps/web/data/policies.json`
- 테스트 수 → `cd apps/web && npm test`
- PR·커밋 수 → `gh pr list --state all | wc -l` · `git rev-list --count main`

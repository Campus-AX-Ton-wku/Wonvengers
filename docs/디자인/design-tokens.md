# Perky 디자인 시스템

색·형태·모션·컴포넌트의 규칙. **값의 단독 출처는 `apps/web/app/globals.css` 의
`@theme` 블록**이고, 이 문서는 왜 그 값인지를 적는다. 화면 파일(`app/**/*.tsx`)에
`#1a6bef` 같은 색값을 직접 쓰지 않는다 — 토큰 이름으로만 쓴다.

> **2026-09-02 전면 교체.** 이전 세계(Navy `#2F4156` · Teal `#567C8D` ·
> Beige `#F5EFEB`)는 마스코트가 없던 시절의 팔레트다. Perky(파란 펭귄 · 노란 탐험
> 모자 · 갈색 크로스백)를 화면에 들이자 캐릭터만 떠 보였다 — 저채도 회청색 지면
> 위에 고채도 파랑·노랑 캐릭터가 서면 둘이 같은 앱으로 읽히지 않는다.
> 그래서 색을 캐릭터에서 다시 뽑았다.

---

## 이 시스템이 지키는 것

1. **accent(금색)는 금액에만.** 일반 강조에 쓰면 "이 색 = 받을 수 있는 돈" 신호가 죽는다.
2. **색만으로 상태를 말하지 않는다.** 모든 상태 배지·안내에 아이콘이나 글자가 함께 온다.
3. **캐릭터는 상태를 말하는 자리에만, 한 화면에 한 포즈.** 장식으로 쓰지 않는다.
4. **아이콘은 `lucide-react` 한 벌.** 이모지를 기능 자리에 쓰지 않는다.
5. **새 색을 쓰기 전에 대비부터 잰다.** 본문 4.5:1, 18px 이상 굵은 글씨 3:1 (WCAG AA).

파란 지면 위에서 탁하게 뜨지 않는다.

### accent — Perky 금색 (금액 전용)

모자와 전달자 포즈의 ₩ 동전에서 왔다.

| 토큰 | 값 | 용도 | 대비 |
|---|---|---|---|
| `accent-700` | `#7a4e00` | 금액 라벨, 단독 예상액, 산식 | 7.20:1 (흰 배경) |
| `accent-600` | `#8a5a00` | **금액 글씨** | 5.93:1 (흰 배경) |
| `accent-400` | `#ffc629` | 캐릭터의 노랑 그대로 | **면 전용 — 흰 배경 위 1.7:1** |
| `accent-100` | `#ffeab0` | 온보딩 결과 단계의 광원 | **텍스트 금지** |
| `accent-50` | `#fff6e0` | 금액 상자 배경 | `accent-700` 6.69:1 |

**받는 돈에만 쓴다.** 같은 카드의 `최종 예상 주거비`는 내는 돈이라 `ink-900` 이다.
둘 다 물들이면 신호가 죽는다.

**마감된 정책의 금액에는 쓰지 않는다.** 지금 신청할 수 없는 금액에 이 색을 주면
목록에서 가장 큰 혜택처럼 읽힌다 (`app/__tests__/closed-policy-weight.test.tsx` 가 고정).

### 상태

| 상태 | 면 / 글자 | 대비 | 아이콘 |
|---|---|---|---|
| 가능성 있음 · 예상적용 | `ok-50` `#e6f6ee` / `ok-700` `#0d6b43` | 5.87:1 | `CircleCheck` |
| 확인 필요 · 조건충족시가능 | `warn-50` `#fff1e6` / `warn-800` `#9a3412` | 6.60:1 | `TriangleAlert` |

| 접수 마감 · 신청불가 | `ink-100` / `ink-600` | 5.44:1 | `Ban` |
| 정보 | `brand-50` / `brand-800` | 7.10:1 | `Info` |
| 입력 오류 | `danger-50` `#fdecec` / `danger-700` `#a11f18` | 8.0:1 | `CircleAlert` |

`warn`(주황 `#9a3412`)과 `accent`(금색 `#8a5a00`)는 색상환에서 20° 밖에 안 떨어져
있다. 그래도 헷갈리지 않는 이유는 **맥락과 크기가 완전히 다르고**(작은 배지 vs 큰
금액), 배지에는 언제나 아이콘과 글자가 붙기 때문이다. 색으로만 갈랐다면 붙였을 것이다.

### 지면

| 토큰 | 값 | 용도 |
|---|---|---|
| `canvas` | `#f4f8ff` | 페이지 배경 (아주 옅은 블루) |
| `surface` | `#ffffff` | 카드, 시트, 입력칸 |

**예전에는 지면도 카드도 흰색이었다.** 그래서 정책 카드끼리 구분되지 않아 hairline
을 그어야 했고, 그 선이 목록을 표처럼 보이게 했다. 지면을 옅은 파랑으로 내리자
흰 카드가 저절로 떠올라 선이 필요 없어졌다.

## 형태

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `rounded-control` | `1rem` | 버튼, 입력칸, 선택지, 배지 밖 블록 |
| `rounded-card` | `1.25rem` | 카드, 시트, 광고성 배너 |
| `rounded-full` | — | 상태 배지, 답변 칩, 아이콘 버튼 |

Perky 는 모서리가 둥근 캐릭터다. 컨트롤과 카드가 같은 곡률을 공유해야 캐릭터와
같은 물건으로 읽힌다.

### 깊이

| 토큰 | 쓰는 곳 |
|---|---|
| `shadow-card` | 지면 위에 올라온 흰 카드 |
| `shadow-raised` | 시트, 휠 피커 패널 |
| `shadow-sticky` | 하단 고정 CTA 위쪽 — "아래에 더 있다" 신호 |

그림자 색은 검정이 아니라 `rgba(11,42,74,…)` 다. 파란 지면 위 중성 회색 그림자는
탁하게 뜬다. offset 과 blur 를 함께 준다 — 0 offset 컬러 헤일로는 깊이가 아니라 장식이다.

**카드 안에 카드를 넣지 않는다.** 카드 안 보조 블록은 `ink-50` / `accent-50` 면으로
구분하고 그림자를 주지 않는다. 그림자가 겹치면 깊이가 거짓말을 한다.

## 컴포넌트

전부 `apps/web/app/components/` 에 있고, 화면은 `@/app/components` 배럴에서만
가져온다. 개별 파일을 직접 import 하기 시작하면 같은 버튼이 화면마다 갈라진다 —
리디자인 전이 정확히 그 상태였다.

| 컴포넌트 | 하는 일 |
|---|---|
| `AppShell` | 지면 — `max-w-lg`, 좌우 20px, `min-h-dvh` |
| `TopBar` | 뒤로가기(함수 또는 링크) + 워드마크 |
| `StickyBottomAction` | 하단 고정 영역, safe-area 여백 포함 |
| `Button` / `LinkButton` | `primary` · `secondary` · `quiet` × `lg`(56px) · `md`(44px) |
| `IconButton` / `IconLink` | 44px 타깃. `label` 이 **필수** |
| `Card` | `plain` · `flat` · `info` · `notice` |
| `ChoiceCard` | 세로 선택지. 선택 표시는 색 + 체크 + `aria-pressed` |
| `StatusBadge` | 상태 6종. 아이콘이 항상 붙는다 |
| `StepHeader` / `AnsweredStack` | 질문 제목 · 답한 질문 쌓기(진행률 대신) |
| `Field` / `FieldGroup` / `FieldError` / `MoneyInput` / `NumberInput` | 입력 |
| `Disclosure` | `<details>` 기반 접기. 라벨에 건수를 적는다 |
| `EmptyState` | 캐릭터 + 이유 + 다음 행동 |
| `ResultSummary` | 2층 결과의 두 숫자 |
| `PerkyCharacter` | 8종 포즈 |
| `Wordmark` / `HomeMark` | 워드마크 — 'P' 위의 새싹 두 잎 |

여기에 없는 것은 공통이 아니다. 한 화면에서만 쓰는 조각은 그 화면 옆에 둔다
(예: `app/find/PolicyCard.tsx`).

### 지켜야 할 DOM 구조

테스트가 세 곳의 형제 관계를 짚는다. 사이에 래퍼를 끼우면 깨진다.

- `app/find/PolicyCard.tsx` — 루트가 `<article>`, `공고 상한` 라벨의 **바로 다음
  형제**가 금액, 상태 배지의 **부모의 바로 다음 형제**가 기관·마감 줄
- `app/components/ResultSummary.tsx` — 루트가 `<section>`, 두 금액 라벨의 **바로 다음
  형제**가 각각 금액. 지원금 쪽만 `accent`, 글씨 등급도 지원금이 더 커야 한다
- `StatusBadge` — 라벨이 **직접 자식 텍스트 노드**여야 한다. 한 겹 더 감싸면
  `getByText` 가 색 클래스가 붙은 요소를 놓친다

  그것을 대신하지 않는다

## 아이콘

`lucide-react` 한 벌. **직접 import 하지 말고 `app/components/icons.tsx` 를 거친다.**
한곳을 지나야 굵기·크기 규칙이 유지되고, 어떤 아이콘이 이미 쓰이는지 보인다.

- 규격: stroke 2 · 24 그리드 · 라운드 캡 · `currentColor` (lucide 기본값)
- 크기: `ICON_SM`(16) 캡션·배지 · `ICON_MD`(20) 버튼·목록 · `ICON_LG`(24) 상단바
- 아이콘만 있는 버튼은 `IconButton` 을 써서 접근 가능한 이름을 반드시 붙인다

**기능 자리에 이모지를 쓰지 않는다.** 예전에는 섹션 라벨이 🧩 💳 🏦, 경고가 ⚠️,
선택 표시가 ✓ 였다. OS 마다 다른 그림이 나오고 색·굵기가 제멋대로라 같은 화면에
아이콘 체계가 둘 있는 셈이었다.

## 모션

어휘를 다섯 개로 제한한다. 새 애니메이션을 만들기 전에 이 중 하나로 되는지 먼저 본다.
**곡선은 전부 `cubic-bezier(0.16, 1, 0.3, 1)`** — 빠르게 나타나 부드럽게 멈추고,
오버슈트가 없다.

| 클래스 | 움직임 | 시간 | 쓰는 곳 |
|---|---|---|---|
| `step-in` | 오른쪽에서 16px | 0.22s | **화면 전진** — 질문·목록·결과 |
| `rise-in` | 아래에서 12px | 0.5s | 랜딩 요소, 금액 상자 내부 |
| `stagger-in` | 아래에서 8px, 순차 | 0.26s | 목록 카드 (45ms × 순번, **상한 225ms**) |
| `slide-in` | 아래에서 14px | 0.42s | 온보딩 슬라이드 |
| `amount-in` / `amount-reveal` | scale + 떠오름 | 0.42s / 0.6s | **결과 금액** |

규칙:

1. **전진은 `step-in` 하나로 통일한다.** 화면마다 다른 방향으로 들어오면 흐름이
   어디로 가는지 읽히지 않는다.
2. **금액 모션은 금액에만.** 이 앱의 모든 흐름이 두 숫자를 만들기 위해 있다.
   오버슈트를 쓰지 않는 이유: 돈이 튀어오르면 경박해진다. `scale` 도 0.97 로 얕게 둔다.
3. **stagger 지연에는 상한을 둔다.** 없으면 카드가 늘어날 때 마지막 장이 늦게 와서
   화면 전체가 느려 보인다.
4. **`prefers-reduced-motion` 을 반드시 같이 넣는다.** `both` 를 쓰는 애니메이션은
   `animation: none` 만으로는 사라진 채로 남으므로 `opacity: 1; transform: none` 까지
   되돌린다. 움직임만 덜어내고 보임·색은 유지한다. 트랜지션은 끄지 않고 0.01ms 로
   줄인다 — 완전히 없애면 버튼이 죽은 것처럼 보인다.

## 브라우저가 그리는 부분

디자인 시스템 밖으로 새기 가장 쉬운 자리다. `globals.css` 에서 전부 팔레트 안에 둔다.

| 대상 | 값 |
|---|---|
| `::selection` | `brand-200` 면 + `ink-900` 글자 |
| `caret-color` | `brand-600` |
| `accent-color` (체크박스·라디오) | `brand-600` |
| `scrollbar-color` | `ink-200` |
| 링크 밑줄 | `text-underline-offset: 0.2em` — 붙으면 한글 받침을 자른다 |
| `<select>` 화살표 | `ink-600` 셰브론 SVG. OS 기본 화살표는 기기마다 다르다 |
| 포커스 링 | `.focus-ring` 유틸 하나. `brand-700` + 2px offset |

## 접근성

- 터치 타깃 44px 이상. 아이콘은 키우지 않고 여백으로 타깃만 키운다
- 포커스는 `.focus-ring` 하나로 통일. offset 이 있어 파란 버튼 위에서도 링이 지면에 그려진다
- 상태를 색만으로 말하지 않는다 (아이콘 + 글자 + `aria-pressed` / `aria-current`)
- 입력 오류는 `role="alert"`, 입력칸은 `aria-invalid`
- 온보딩은 단계가 바뀌면 제목으로 포커스를 옮긴다. `aria-live` 는 쓰지 않는다 —
  포커스 이동과 겹쳐 같은 내용을 두 번 읽는다
- `viewport-fit=cover` + `env(safe-area-inset-*)` 로 노치·홈 인디케이터를 피한다

## 타이포그래피

한글은 어절 중간에서 끊기는 것이 기본값이라(`지원사 / 업`) `word-break: keep-all` 을
`body` 에 건다. 끊을 자리가 없는 긴 URL 이 지면을 뚫지 않게 `overflow-wrap: break-word`
를 짝으로 둔다.

| 자리 | 값 |
|---|---|
| 화면 제목(질문·온보딩) | 26~28px / 800 / `leading-[1.35]` |
| 섹션 제목 | 20~24px / 800 |
| 본문 | 15~16px / 400~500 / `leading-relaxed` |
| 메타·캡션 | 11~13px |
| 금액 (2층 결과) | 36px `text-4xl` / 800 / `tabular-nums` |
| 금액 (1층 요약) | 46px / 800 |

`leading-tight`(1.25)은 26px 한글에서 윗선이 잘린다. 한글은 라틴보다 글자틀이 크고
받침이 아래로 내려가므로 1.35 는 있어야 두 줄이 안 붙는다.

두 줄짜리 제목은 `\n` 으로 **직접 끊는다**. 자동 줄바꿈은 "생년월일이 어떻게 /
되시나요?" 처럼 의미 단위를 무시한다.

**세로로 쌓이는 금액에는 `tabular-nums`.** 비례폭 숫자는 자릿수마다 폭이 달라서
금액이 세로로 쌓이면 천 단위가 흔들린다. 단, **1층 카드의 공고 상한에는 쓰지
않는다** — 표가 아니고, 이 폰트에서 등폭 숫자가 벌어져 '4 80만원' 처럼 읽힌다.

## 폰트

**Pretendard 를 웹폰트로 직접 싣는다** (`app/layout.tsx`, `next/font/local`).
폴백은 `Apple SD Gothic Neo` → `Malgun Gothic` → `sans-serif` 로 남긴다.

전에는 이 스택을 CSS 에 적기만 하고 파일을 부르지 않았다. 그래서 Pretendard 가
설치된 사람만 그 글꼴을 봤고 나머지는 기기별 폴백을 봤다 — 윈도우는 Malgun
Gothic, 맥·iOS 는 Apple SD Gothic Neo. 셋 다 멀쩡한 고딕이지만 자폭과 굵기가
달라 같은 화면이 기기마다 다르게 읽혔고, 발표 덱의 캡처와 심사위원 폰의 화면이
어긋났다.

파일은 상용 한글까지 남긴 가변 폰트 서브셋이다 (434KB). 실측 비교:

| 후보 | 크기 | 한글 |
|---|---|---|
| PretendardVariable (원본) | 2,009KB | 11,172자 |
| Pretendard-Regular (정적 1웨이트) | 748KB | 11,172자 |
| 현대 한글 전체로 서브셋 | 1,694KB | 11,172자 |
| **서브셋 — 쓰는 것** | **434KB** | **2,350자 (KS X 1001)** |
| 앱이 쓰는 글자만 | 144KB | 607자 |
| ~~PretendardStd~~ | 285KB | **0자 — 라틴 전용, 쓰지 말 것** |

**앱이 쓰는 글자만 담지 않는 이유.** 144KB 까지 줄지만, 그러면 한글 주석을 고칠
때마다 `font-coverage` 테스트가 실패한다. 이 레포는 주석이 한글로 두껍다. 게다가
재생성에는 `fontTools`·`brotli` 와 원본 폰트 2MB 가 필요해서, 도구가 없는 팀원은
빨간 테스트를 스스로 풀 수 없다. 290KB 를 더 내고 그 상황을 없앤다.

현대 한글 전체(1,694KB)로는 가지 않는다. 상용 한글 밖으로 새는 것은 `뷁` 같은
무의미어나 `똠얌꿍` 수준이다.

`PretendardStd` 는 이름이 서브셋처럼 보이지만 한글 글리프가 없다. 크기만 보고는
알 수 없어서 한 번 잘못 넣었다.

서브셋을 다시 만드는 법은 `apps/web/scripts/build-font-subset.py` 에 있다.
서브셋에 없는 글자는 폴백으로 그려져 문장 중간에서 글꼴이 갈리는데 에러가 나지
않으므로 `lib/__tests__/font-coverage.test.ts` 가 소스·정책 데이터의 한글을
검사한다. 정책 문구가 바뀌면 그 테스트가 먼저 실패한다.

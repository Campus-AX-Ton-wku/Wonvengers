# Perky 디자인 토큰

색은 `apps/web/app/globals.css`의 `@theme` 블록 **한 곳**에만 정의한다.
화면 파일(`app/**/*.tsx`)에 `#2F4156` 같은 색값을 직접 쓰지 않는다. 토큰 이름으로만 쓴다.

**팔레트 출처:** `docs/디자인/reference/color-reference.jpg`
Navy `#2F4156` · Teal `#567C8D` · Sky `#C8D9E6` · Beige `#F5EFEB` · White

**모바일 앱 형태의 화면 구조 레퍼런스:** 타사 앱(토스·삼쩜삼) 화면 캡처.
상단 앱바(뒤로가기 + 진행률) / 카드 없는 지면 / 세로 선택 카드 / 하단 고정 CTA 가
공통 패턴이고, 2층 스텝 화면이 이 구조를 따른다.

> **`docs/디자인/reference/` 는 저장소에 올리지 않는다.** 타사 앱 화면 캡처라
> public 저장소에 두지 않고 각자 로컬에만 보관한다 (`.gitignore` 에 등록됨).
> 추출한 색과 규칙은 이 문서로만 공유한다.

이 문서는 1층(`/find`)과 2층(`/calculate`~`/result`) 양쪽에 모두 적용된다.

**지면은 흰색이다.** Perky는 베이지(`sand-100`)를 지면으로 썼지만 이 앱은 흰 배경을 쓴다.
아래 대비 수치는 전부 흰 배경 기준이라 그대로 유효하다.

## 지켜야 할 규칙

1. **`ink-200`, `brand-200`, `sand-200` 위에 글씨를 올리지 않는다.**
   면과 보더 전용이다. 실측: `sand-200` + `ink-600` = **4.27:1**, `sand-200` + `ink-500` = **3.94:1**
   로 둘 다 본문 기준(4.5:1) 미달이다. 결과 화면의 `대상아님`·`신청불가` 태그가 이 조합을
   쓰고 있었고 `ink-100` 면으로 고쳤다 (2026-08-23).

   `ink-100`(`#E8EDF2`)과 `sand-50`(`#FAF7F5`)은 거의 흰색이라 예외다 —
   `ink-100` + `ink-700` = 5.75:1, `ink-100` + `ink-600` = 4.76:1, `sand-50` + `ink-600` = 5.25:1.
   고지 문구 상자와 비활성 카드가 이 조합을 쓴다.

2. **본문 텍스트는 `ink-600` 이상만 쓴다.**
   `ink-500`이 가장 옅게 허용되는 텍스트 색이고, 그보다 옅은 토큰은 없다.
   Tailwind 기본 팔레트의 `text-stone-400`(2.77:1) 같은 색을 되살리지 않는다.

3. **`brand-600`은 배경이나 큰 글씨로만 쓴다.**
   흰 배경 위 대비가 4.50:1로 본문 기준을 겨우 통과한다. 링크나 작은 라벨에는
   `brand-700`(6.44:1)을 쓴다. 버튼 배경으로 쓸 때 그 위 글자는 흰색(4.50:1).

4. **색을 새로 추가하려면 대비부터 확인한다.**
   기준: 본문 4.5:1, 18px 이상 굵은 글씨 3:1 (WCAG AA).
   확인 도구: https://webaim.org/resources/contrastchecker/

## 폰트

**Pretendard 를 웹폰트로 직접 싣는다** (`app/layout.tsx`, `next/font/local`).
폴백은 `Apple SD Gothic Neo` → `Malgun Gothic` → `sans-serif` 로 남긴다.

전에는 이 스택을 CSS 에 적기만 하고 파일을 부르지 않았다. 그래서 Pretendard 가
설치된 사람만 그 글꼴을 봤고 나머지는 기기별 폴백을 봤다 — 윈도우는 Malgun
Gothic, 맥·iOS 는 Apple SD Gothic Neo. 셋 다 멀쩡한 고딕이지만 자폭과 굵기가
달라 같은 화면이 기기마다 다르게 읽혔고, 발표 덱의 캡처와 심사위원 폰의 화면이
어긋났다. 아래 "유니코드 글리프를 아이콘 자리에 쓰지 않는다" 와 같은 이유다.

파일은 상용 한글까지 남긴 가변 폰트 서브셋이다 (434KB). 실측 비교:

| 후보 | 크기 | 한글 |
|---|---|---|
| PretendardVariable (원본) | 2,009KB | 11,172자 |
| Pretendard-Regular (정적 1웨이트) | 748KB | 11,172자 |
| 현대 한글 전체로 서브셋 | 1,694KB | 11,172자 |
| **서브셋 — 쓰는 것** | **434KB** | **2,350자 (KS X 1001)** |
| 앱이 쓰는 글자만 | 144KB | 607자 |
| ~~PretendardStd~~ | 285KB | **0자 — 라틴 전용, 쓰지 말 것** |

**앱이 쓰는 글자만 담지 않는 이유.** 144KB 까지 줄지만, 그러면 한글 주석을 고칠
때마다 `font-coverage` 테스트가 실패한다. 이 레포는 주석이 한글로 두껍다. 게다가
재생성에는 `fontTools`·`brotli` 와 원본 폰트 2MB 가 필요해서, 도구가 없는 팀원은
빨간 테스트를 스스로 풀 수 없다. 290KB 를 더 내고 그 상황을 없앤다.

현대 한글 전체(1,694KB)로는 가지 않는다. 상용 한글 밖으로 새는 것은 `뷁` 같은
무의미어나 `똠얌꿍` 수준이다.

`PretendardStd` 는 이름이 서브셋처럼 보이지만 한글 글리프가 없다. 크기만 보고는
알 수 없어서 한 번 잘못 넣었다.

서브셋을 다시 만드는 법은 `apps/web/scripts/build-font-subset.py` 에 있다.
서브셋에 없는 글자는 폴백으로 그려져 문장 중간에서 글꼴이 갈리는데 에러가 나지
않으므로 `lib/__tests__/font-coverage.test.ts` 가 소스·정책 데이터의 한글을
검사한다. 정책 문구가 바뀌면 그 테스트가 먼저 실패한다.

## accent — 금액 (Terracotta 계열)

**금액 강조색을 테라코타로 확정했다.** 팔레트 5색이 전부 저채도라 "금액"이라는
신호를 낼 색이 없었다. 베이지와 붙는 계열로 골라 기존 팔레트와 충돌하지 않는다.

| 토큰 | 값 | 용도 | 흰 배경 대비 |
|---|---|---|---|
| `accent-700` | `#8F4526` | hover · 눌린 상태 | 6.89:1 |
| `accent-600` | `#A85434` | **금액 글씨**, 지원금 강조 | 5.27:1 |
| `accent-200` | `#E7CFC6` | 옅은 면 | **텍스트 금지** |
| `accent-50` | `#F9F3F1` | 금액 상자 배경 | **텍스트 금지** |

`accent-600`은 `accent-50` 위에서 4.80:1, 흰 글씨를 올려도 5.27:1로 세 조합
모두 AA를 통과한다.

> **이 색은 금액과 지원금에만 쓴다.** 일반 강조에 쓰기 시작하면 "이 색 = 돈"이라는
> 신호가 죽는다. 버튼·링크·선택 상태는 계속 `brand-*`를 쓴다.

현재 사용처:
- 결과 화면의 `최대 지원 가능액` (`app/result/page.tsx`)

랜딩에서는 쓰지 않는다. 예전에는 히어로 건물 그래픽의 창 하나를 이 색으로 켰는데,
그래픽을 지우면서 함께 없어졌다. 랜딩은 `ink-900` 워드마크와 `brand-600` CTA 뿐이다 —
금액을 아직 헤드라인에 걸 수 없으므로(`MAX_BENEFIT` 주석 참고) 이 색이 나설 자리가 없다.

**받는 돈에만 쓴다.** 같은 상자의 `최종 예상 주거비`는 내는 돈이라 `ink-900`으로 둔다.
둘 다 물들이면 "이 색 = 지원금" 신호가 죽는다.

## 아이콘

`apps/web/app/icons.tsx` 에 직접 그린 SVG 로 둔다. 규칙은 **stroke 2 · 라운드 캡 ·
24 그리드 · `currentColor`** 로, `Stepper.tsx` 의 뒤로가기·체크 아이콘과 같다.

**유니코드 글리프(`−` `+` `✓`)와 이모지(⚠️)를 아이콘 자리에 쓰지 않는다.**
폰트에 따라 두께·크기·정렬이 제멋대로 달라지고, 같은 화면 안에서 굵기가 어긋난다.

## 이모지

**기능 아이콘과 톤 이모지를 구분한다.**

| | 쓰는 것 | 예 |
|---|---|---|
| 기능 아이콘 | 직접 그린 SVG (`app/icons.tsx`) | 나이 −/+ · 토글 화살표 · 경고 표시 · 뒤로가기 |
| 톤 이모지 | 유니코드 이모지 | 질문 제목(🎂 📍 🎓 💰) · 스텝 제목(🙋 👨‍👩‍👧 📄) · 섹션 라벨(💳 🧩 🏦) · 빈 상태(🔍) |

이모지는 **읽는 데 필요 없는 장식**이므로 `<span aria-hidden="true">` 로 감싼다.
감싸지 않으면 스크린리더가 "생일 케이크"를 읽어 질문 자체를 가린다.

이모지를 쓰지 않는 곳:
- **금액·태그·버튼 라벨** — 숫자와 판정이 주인공이다. 옆에 이모지를 붙이면 시선이 갈린다.
- **랜딩 전체** — 96px 워드마크 하나가 톤을 다 나른다. 이모지도, 그래픽도 없다.

## 모션

어휘를 네 개로 제한한다. 새 애니메이션을 만들기 전에 이 중 하나로 되는지 먼저 본다.

| 클래스 | 움직임 | 시간 | 쓰는 곳 |
|---|---|---|---|
| `step-in` | 오른쪽에서 16px 밀려 들어옴 | 0.22s ease-out | **화면 전진** — 1층 질문·목록, 2층 스텝, 결과 |
| `rise-in` | 아래에서 12px 떠오름 | 0.5s ease-out | 랜딩 요소, 금액 상자 내부 |
| `stagger-in` | 아래에서 8px, 순차 | 0.26s ease-out | **목록으로 등장하는 카드** (지연 45ms × 순번, **상한 225ms**) |
| `amount-in` | scale 0.97 → 1 | 0.42s `cubic-bezier(0.16, 1, 0.3, 1)` | **결과 금액 상자와 캡처 카드** — 화면에서 유일하게 공들인 도착 |

규칙:

1. **전진은 `step-in` 하나로 통일한다.** 화면마다 다른 방향으로 들어오면 흐름이 어디로
   가는지 읽히지 않는다.
2. **`amount-in` 은 금액에만 쓴다.** 이 앱의 모든 흐름이 두 숫자를 만들기 위해 있다.
   다른 곳에 쓰면 "여기가 결론"이라는 신호가 죽는다. 오버슈트 곡선을 쓰지 않는 이유:
   돈이 튀어오르면 경박해진다. `scale` 도 0.97 로 얕게 둔다 — 크게 잡으면 모달로 읽힌다.
3. **stagger 지연에는 상한을 둔다.** 상한이 없으면 카드가 늘어날 때 마지막 장이 늦게
   와서 화면 전체가 느려 보인다.
4. **`prefers-reduced-motion` 경로를 반드시 같이 넣는다.** `both` 를 쓰는 애니메이션은
   `animation: none` 만으로는 사라진 채로 남으므로 `opacity: 1; transform: none` 까지
   되돌린다. 움직임만 덜어내고 보임·색은 유지한다.

## 세로로 쌓이는 금액

`tabular-nums` 를 붙인다. 비례폭 숫자는 자릿수마다 폭이 달라서 금액이 세로로
쌓이면 소수점·천 단위가 흔들린다. 적용: 결과 화면과 요약 화면의 금액 두 줄,
조합 목록의 금액.

## 선택 영역

`::selection` 을 `brand-200` 면 + `ink-900` 글자로 둔다 (`globals.css`).
브라우저 기본 파랑은 팔레트 밖 색이고, 캡처해서 공유되는 화면이라 눈에 띈다.
